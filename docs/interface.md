# gatectl: interface

Status: designed, 2026-11-10 (interface 0.1.0-design). This document is the single normative source for gatectl's rules. `design.md` records the decisions and the internal structure and links to the headings here instead of restating them; the README, the architecture and the schemas follow it. Machine-readable shapes are in `schemas/`.

## Concepts

gatectl answers one question for a caller: may this step go ahead? A caller sends a JSON object describing the step (typically a hook payload) and names a **policy**. gatectl runs the policy's checks and returns a **decision** (`allow`, `deny` or `escalate`) with a reason, and records it. Callers that act on the answer are separate tools; gatectl never performs the step. Terms defined later are used earlier in places: Track records and recommendation, Check order, Residual risks, declared fields (Input declaration) and effective definition (Fingerprint).

### Identifiers

- **Policy name:** `^[a-z0-9][a-z0-9_-]{0,63}$`. A policy name that is neither in the config nor in `state.db` is a usage error (exit 2) in every command (error envelope `code: usage`, `details.kind: unknown_policy`). A name that is only in `state.db` (a removed or renamed policy) is accepted read-only by `decisions`, `stats` and `show` (rows are marked `configured: false`) and by `set <name> off|shadow`, which is how its rows are lowered before the name is reused; `check` and `set ... enforced` exit 2 for it, and `policies` lists only configured policies.
- **Decision id:** `gd-` followed by 12 lowercase base32 characters (`a-z`, `2-7`), generated from random bytes. Commands accept the full id or a unique prefix of at least 6 characters after `gd-`; the `gd-` is stripped once when present, and the rest must be base32 (`a-z`, `2-7`) before any lookup (a `%` or `_` is a usage error, exit 2). A shorter prefix exits 2, an ambiguous one exits 21, an unknown one exits 10. The id satisfies the hook decision-id grammar callers validate (`^[A-Za-z0-9._:@/-]{1,128}$`). A decision id is a reference to a recorded decision, not an authorization. The id is generated once per `check`: when the first script or agent check needs `tmp/<decision_id>/`, else when a decision is recorded at step 8. The same id names the directory, the session label and the recorded decision. A probe generates a `gd-` id the same way and records no decision.
- **Repo id:** `host/<full project path>` as in the design guide: a lowercase host with an optional `:port`, then `/` and path segments of `[A-Za-z0-9._-]`. The grammar is matched against the whole string, is at most 255 characters, and a path segment of `.` or `..` is invalid. A repo is compared exactly as written (no case folding; callers pass one spelling). gatectl never derives a repo from the working directory (hooks run in untrusted directories). The repo is `--repo`, else the input object's top-level `repo`. A `--repo` flag value that fails the grammar exits 2 in every command that takes it (`check` never accepts `*`; Scope lists the commands that do). `--repo` is the trusted source: when it is given, the payload `repo` never selects the scope or the state, a valid payload `repo` that differs adds the warning `repo_mismatch`, an invalid one adds `repo_invalid`, and nothing else changes. Without `--repo`, a payload `repo` that is absent or JSON `null` selects scope `*`. That is an ordinary input, not an error: many callers act on objects that belong to no repository, so a payload with no `repo` is scoped `*` with no warning, and `input: {require: [repo]}` is the way to insist on one. The scope is **indeterminate** when there is no `--repo` and either the payload `repo` is present and is not a valid repo id (a non-string, or a string failing the grammar; warning `repo_invalid`) or the input is unusable (over `input_max_bytes`, not a strict JSON object, or not fully read by the deadline), because no repo can be trusted. For an indeterminate scope the decision is `escalate` (Check order, steps 2 and 5), its scope is `*`, and its state is the strictest state (`enforced` over `shadow` over `off`) among the policy's stored rows when it has any, and the config's initial state only when it has none (so `set <policy> off --all` turns an indeterminate input `off` too, a policy with no rows uses its initial state, and a stored `enforced` row anywhere still wins); the state is resolved at step 3 and again at step 8, so a malformed repo, a truncated payload or a stalled writer cannot move an enforced policy to shadow.
- **Scope:** a repo id, or `*` (all repos). A decision's scope is its repo id, or `*` when it has no repo. `--repo '*'` names scope `*` in `decisions`, `stats`, `policies` and `set`; every other use of `*` as a repo exits 2.
- **Check name:** `^[a-z0-9][a-z0-9_-]{0,63}$`, unique within a policy.
- **Signal:** `^[a-z][a-z0-9_-]{0,31}$`, a free label naming where an outcome came from (`human`, `auto`, `revert`, `incident`, anything else).
- **Duration:** `0`, or an integer and a unit: `ms`, `s`, `m`, `h`, `d` (for example `500ms`, `20s`, `10m`). `--timeout` takes a number of seconds (decimals allowed).
- **Time:** every stored and printed timestamp is UTC in the fixed form `YYYY-MM-DDTHH:MM:SS.ffffffZ`. `--since` takes an RFC 3339 time (never naive) or a duration meaning "now minus"; the time accepts only an upper-case `T` and `Z`, a `+hh:mm` or `-hh:mm` offset, no leap second (`:60`), and 1 to 9 fractional digits (cut to 6). Cache reuse and `since` use the wall clock; a cache row dated in the future is ignored.
- **Input hash:** `input_sha256` is the SHA-256 of the canonical serialization of the whole parsed input: the UTF-8 bytes of the value with object keys sorted by Unicode code point, no whitespace (separators `,` and `:`), characters kept as written except those JSON requires to be escaped, integers as written, and other numbers in their shortest round-trip decimal form (Python's `json.dumps(value, sort_keys=True, separators=(',', ':'), ensure_ascii=False)`). When no object was parsed (an input over the cap, not UTF-8, not strict JSON, or not fully read) it is the SHA-256 of the raw bytes read (at most `input_max_bytes` + 1). It is the value in the check result, the audit log and `show`, and the base of the cache key. Test vectors: `{"b":1,"a":"é","c":[1.5,true,null]}` serializes to `{"a":"é","b":1,"c":[1.5,true,null]}` with hash `2332fe002293e35042867b9afd7a8a2a470df3cc466fe44903a5b44f99d16b92`; `{"repo":"github.com/org/repo","head_sha":"0123abcd"}` has hash `82ad1dd601d033fddc136731fab553afa585dd3ad0f9f3745b42708aea02a855`; the raw bytes `not json` have hash `7ccfa1fbf3940e6f0c0375d87c0f9235a50514e14cb427bdfaf5077987b26ccf`.

### Decisions, states and scopes

- **Decision:** `allow`, `deny` or `escalate`. Severity order is `deny` > `escalate` > `allow`.
- **State:** `off`, `shadow` or `enforced`. New policies start in `shadow`; the config's `state` key sets only the initial state and is `off` or `shadow`.
- **Effective state** of a policy for a scope: the stored row for the decision's repo, else the stored row for `*`, else the policy's initial state. State changes happen only through `set` and the automatic drop in Outcomes; a row is never created by `check`.
- **Shadow** means: run everything, record the would-be decision, never block (exit 0). Exit 0 in shadow means "do not block", never "authorize": a caller that uses a gate to enable an automatic action must require `"enforced": true` and `"decision": "allow"` in the result, and otherwise fall back to the manual default. A `not_applicable` answer (Check order, step 4a) evaluated nothing: it prints `shadow: false` and `enforced: false` whatever the scope's state, so it never satisfies that rule and never authorizes an automatic action.

### Actors and human actions

`--actor` is `human:<name>` or `auto:<name>` (`<name>` matches `[A-Za-z0-9._@-]{1,64}`). Without `--actor` the default is `human:<me.name>` when stdin is a TTY, otherwise `auto:unknown`; a `me.name` or OS user name outside the charset has each disallowed character replaced by `_` and is cut to 64 characters (an empty one becomes `user`). The content of `me.name` is never refused and never fails a command: any string of at most 1024 characters is accepted. Only a non-string value (quote a numeric name in YAML) or a value over 1024 characters is a config error. The name reaches the audit log and any output only after this sanitizing. A **human action** is one whose effective actor is `human:<name>`: an explicit `--actor` must be `human:<name>` with a non-blank name (any other explicit actor is not human, even with a TTY), and without `--actor` stdin must be a TTY. An actor is a claim: a same-user process can lie about it, so every human-only rule is advisory against such a process (Residual risks). The audit record carries `stdin_tty` and `actor_source`.

### Untrusted text

Everything that comes from the input, from a check, from an agent or from an `outcome` reason is untrusted: payload values, script output, artifact `reasons`, check `detail`, outcome reasons. The schemas mark these fields `x-untrusted`. gatectl replaces every code point whose Unicode category is `Cc`, `Cf`, `Zl`, `Zp`, `Cs`, `Co` or `Cn`, and any other non-printable character except the space, with the marker `�` before storing or printing it (the stored and printed text only: hashes, the cache key, case keys and `--declared` matching use the original value), caps every length (256 characters unless a field says otherwise), never puts such text in argv or in the environment of any process, and never prints input text outside the declared fields. `--verbose` output and every error `message` go through the same sanitizer and never include input text or a raw flag value.

## Policies

A policy is a named, ordered list of checks plus a declared input. Policies live in the config (`policies:`), in `config.yaml` or any drop-in; there are no policy files. A policy's mutable state lives in `state.db`, never in the config.

```yaml
policies:
  auto-merge:
    state: shadow
    timeout: 60s
    input: {require: [repo, head_sha], types: {repo: string, head_sha: string}}
    checks:
      - {name: ci-green, type: rule, when: [{path: ci.state, op: ne, value: passing}], then: deny}
      - {name: scope, type: script, argv: [/usr/local/bin/check-scope], timeout: 20s}
      - {name: reviewer, type: agent, instruction: "Escalate if the change touches security-sensitive code.", threshold: 0.8}
```

### Policy keys

| Key | Meaning | Default |
|---|---|---|
| `state` | initial state for scopes with no stored row: `off` or `shadow`; `enforced` is a config error whose message says to use `gatectl set` | `shadow` |
| `timeout` | total deadline for one `check` | `defaults.timeout` |
| `applies_when` | a non-empty list of rule conditions, evaluated exactly like a rule check's `when` (ordered, stopping at the first false or error); when one is false the policy does not apply (Check order, step 4a) | none (always applies) |
| `input` | declared input (below) | none |
| `checks` | ordered list, at least one and at most 128 (a longer one is a config error `invalid_value` naming `checks`: a decision's per-check results must stay readable by `show`) | required |
| `cache_ttl` | agent-check reuse window; precedence check > policy > `agent.cache_ttl` | `agent.cache_ttl` |
| `record_input` | also store the canonical input (compact JSON, keys in input order, ASCII escapes; at most `input_max_bytes` of source, since a larger input is unusable and nothing is stored) in `state.db` (never in the audit log) | `false` |
| `recommend` | `{confidence, max_miss_rate}` for Track records and recommendation | `defaults.recommend` |

`applies_when` is a scoping filter, not a detector: write it over fields the caller sets from a trusted source. A condition that fails to match skips the gate. A null on a nullable path makes `eq` with a non-null value an error, which counts as applicable (Rule checks); put `{path: P, op: ne, value: null}` first when a field is null for some actions: a null then makes that condition false, so the gate is skipped.

Unknown keys, an empty or longer-than-128 `checks` list, duplicate check names and a check of an unknown `type` are config errors (exit 2, naming the key; see Config for how far a config error reaches).

### Input declaration

`input` declares the top-level keys the policy needs: `require` is a list of keys that must be present and not `null` unless typed nullable, `types` maps a key to `string`, `integer`, `number`, `boolean`, `object` or `array`, with a trailing `?` for a nullable key (`string?`), and `ignore` lists top-level keys (volatile fields such as a timestamp or an event id) that are left out of the cache key; they are still given to the check, still part of `input_sha256` and still part of the fingerprint. `ignore` may not name `repo` (a config error `invalid_value`: the scope is part of the key, and a payload repo decides it); it also leaves the key out of case identity (Track records and recommendation). `string`, `boolean`, `object` and `array` are the JSON types; `integer` is a JSON number written without a fraction or exponent (`1.0` is not an integer); `number` is any JSON number; booleans are never numbers. A key in `types` but not in `require` may be absent; when present it must match (`null` only with `?`).

The input must be a JSON object of at most `input_max_bytes` (1 MiB) in strict JSON: UTF-8; no `NaN` or `Infinity` token; every number finite after parsing (`1e999` is invalid); no string with an unpaired surrogate (`"\ud800"` is invalid); no duplicate keys at any depth; nesting at most 64, checked without recursion (a pre-scan) before decoding; any error raised while parsing (including number or recursion limits) is `input_invalid`. Declared fields and the identity strings are validated as finite and encodable as UTF-8 before step 5 of Check order, so recording cannot fail on input content. A violation escalates the decision with reason `input_invalid` (never allows, never a usage error); an input that is not a JSON object or does not parse is also `input_invalid` for a known policy. Script checks still receive the whole input.

The values of the keys named in `require` and `types` are the policy's **declared fields**. Their canonical JSON (ASCII-escaped, compact) may total at most 32 KiB; a larger set cannot be recorded and the input is `input_invalid`. A declared string is stored capped at 256 characters; any other declared value whose canonical JSON exceeds 1 KiB is stored as the string `[truncated: <n> bytes]`. gatectl stores no input text outside the declared fields, the identity strings, a script's or agent's `detail` and cached agent `reasons` (which can quote input), unless `record_input` is on. When the input is not parseable or fails the declaration, the declared fields and `tool`, `hook`, `object_type`, `object_id` are null. A policy that gates an action bound to a revision (a head sha, a base ref) should list that key in `require`, so the revision is a declared field of every decision.

The input's top-level `tool`, `hook`, `object_type` and `object_id` are recorded with the decision when present, capped at 256 characters; a present value that is not a string is recorded as null.

### Per-repo overrides

`repos.<repo-id>.policies.<name>` may set any policy key except `state` (a repo's state is its stored row; `state` in an override is a config error naming the key). A key it sets replaces the global key entirely, lists included; nothing merges inside a key, with two exceptions: a key `recommend` set by an override is a whole map in which a missing sub-key takes the value of `defaults.recommend`, and `input` is replaced whole. The decision's scope picks the override, and the override's effective definition has its own fingerprint, state rows and track record. The repo comes from the caller's payload: it selects a configuration and is not a security boundary. `validate` reports an override that names an unknown policy or key.

### Fingerprint

The fingerprint is `sha256:` plus the SHA-256 of the canonical JSON (sorted keys, compact, UTF-8) of the policy's **effective definition** for a scope: the policy name, `input`, `applies_when` (if any) and every check with all of its keys except `timeout` and `cache_ttl`, in a normalized form with every default filled in, so that spelling a default explicitly does not change the fingerprint (a rule's `else: allow` is present, an agent check's `skill`, `model`, `threshold`, `sandbox`, `setting_sources`, `env_allowlist` and `permission_profile` are replaced by their resolved values and the hash below, a script check's `env_allow` is replaced by the effective environment allowlist). An agent check also carries the SHA-256 of its permission-profile file, of its instruction text (the bytes of `instruction_file` or the `instruction` string) and of the `SKILL.md` and `plugin.json` of its skill's plugin. A script check also carries its effective environment allowlist (`defaults.script_env_allow` plus `env_allow`) and the SHA-256 of every `argv` element that is an absolute path to an existing regular file (a file over 1 MiB, in practice an interpreter or a binary, contributes its size and modification time instead; the deadline is checked between files). It excludes `state`, the policy and check `timeout`s, `cache_ttl`, `record_input`, `recommend`, `session_cmd` and the working directory. A file that cannot be read contributes the fixed marker `unreadable`: one that is missing or is not a regular file (an agent check's files; a script's `argv` element that is missing or not a regular file contributes nothing), unreadable by permission, over 64 KiB for an `instruction_file`, changed while it was read, or not reached before the deadline. Files are opened only when they are regular files, without blocking, and streamed, so a FIFO, a device or a huge file is never read whole; a link is followed; a file over 1 MiB (any hashed file but an `instruction_file`) contributes its size and modification time. A skill that cannot be found contributes the marker for its `SKILL.md` and `plugin.json`; computing the fingerprint never fails and never depends on the caller's working directory. A skill's `plugin.json` is also read up to 1 MiB to learn the plugin's name; a larger one cannot identify its plugin, so the skill counts as not found. A check-level `model: null` or `permission_profile: null` is the same as absent and inherits the `agent:` block value. The order of `input.require`, `input.ignore` and `checks` is covered; `setting_sources`, `env_allowlist` and `env_allow` are order-independent; an absent `input` equals an empty declaration. A file is read twice and must give the same bytes both times, with size, modification and change times unchanged during each read, else it is `unreadable`. Editing anything it covers starts a fresh track record.

## Checks

Checks of the three types below run in a fixed order (Check order). Every check yields a **verdict** (`allow`, `deny`, `escalate`, or `skipped` for a check that did not run: a script or agent check after the deadline, any later check (rule, script or agent) after a `deny`, or an agent check after an `escalate`; a rule check is never skipped for the deadline) and a **reason code** from the closed list in Reasons. `checks` in the result and in the record lists every check of the effective policy in execution order: rule and script checks in listed order, then agent checks in listed order (the YAML order of mixed types is not kept). A `skipped` check has `reason: null`, `detail: null`, `duration_ms: 0`, and for an agent check `confidence: null`, `reused: false`. When the declaration fails (`input_invalid`), `checks` is empty. "Check order" means this execution order everywhere (the reason of the first `escalate` is the first in it).

### Script checks

```yaml
- {name: scope, type: script, argv: [/usr/local/bin/check-scope], timeout: 20s, env_allow: [SCOPE_DIR]}
```

- `argv` is a list, never a shell string. `argv[0]` must be an absolute path (a config error otherwise). Whether it exists and is executable is checked when the check starts, never at load; a missing or non-executable file escalates with reason `tool_missing`. Other elements are passed as given: a relative path-like element (it contains `/` and is not absolute) is never resolved and never hashed, and `validate` warns `relative_argv`.
- The input JSON is written to the check's stdin without blocking and bounded by the check's timeout; a closed pipe is ignored. The check runs in a private empty directory `tmp/<decision_id>/s-<n>/` (mode 0700, `<n>` counting the script checks of this process from 1), removed after the check (Files, Removal of `tmp/` trees), in its own process group that gatectl creates and records, with a timeout (`timeout`, default `defaults.script_timeout`, capped by the remaining budget). stdout and stderr are each read up to 64 KiB; more than that is discarded and noted with the warning `output_truncated`. stderr is read (so the pipe cannot fill) up to 64 KiB and then discarded; it is never stored or printed. The `detail` of a check that did not allow comes from the stdout `reason` when there is one, else is `exit <n>`, `signal <n>`, `timeout`, `not started` or `lifeline lost`. A reason that is empty after sanitising (only spaces and replacement markers) is treated as absent, so the detail falls back to the forms above.
- The environment is built from scratch from `defaults.script_env_allow` (default `PATH`, `HOME`, `LANG`, `LC_*`) plus the check's `env_allow`; a variable that is not in the allowlist never reaches the check, so token variables stay out unless a check names one. `env_allow` entries are exact names matching `^[A-Za-z_][A-Za-z0-9_]*$`; only `defaults.script_env_allow` accepts a trailing `*`. The `PATH` a check receives has empty and relative entries removed.
- **The exit code decides:** 0 is `allow`, 11 is `deny`, 13 is `escalate`, anything else (a crash, a signal, `126`, `127`, `2`, a timeout) is `escalate` with reason `check_error` (`timeout` for a timeout). stdout may be one strict JSON object with an optional `reason` string (at most 1024 characters, kept as the check's `detail`; a longer one is truncated, not dropped) and an optional `decision`; an unknown key in the object is ignored; a `decision` that is present but is not exactly one of the strings `allow`, `deny` or `escalate` (including `null`, a wrong case or a non-string) or that disagrees with the exit code counts as a disagreement and escalates (`check_error`). A parse failure of the output drops only the `detail`, never the verdict. An exit code of 256 wraps to 0 and cannot be told from a clean 0 (Residual risks).
- On a timeout or when the decision ends early, gatectl signals the check's process group (SIGTERM, then SIGKILL after a 2 s grace). Completion is detected without reaping the leader (`waitid` with `WNOHANG | WNOWAIT`), so the group id cannot be reused before the sweep; gatectl kills the remaining group, tells the lifeline watchdog `done`, and only then reaps the leader. A lifeline pipe makes a watchdog kill the group if gatectl itself dies. gatectl also watches the watchdog: if the watchdog is already gone when the check has been registered, the check is killed at once and ends `check_error` with detail `not started` (it may have run for a few microseconds before the kill); if the watchdog exits at any later time before `done`, the check is stopped as on a timeout (SIGTERM, then SIGKILL after the grace) and ends `check_error` with detail `lifeline lost`, whatever its exit code was. A check never runs unguarded to an `allow`. A process that calls `setsid` leaves the group and is not killed (Residual risks).

### Rule checks

```yaml
- name: ci-green
  type: rule
  when:
    - {path: ci.state, op: ne, value: passing}
  then: deny
  else: allow
```

A rule is a pure function of the input: no process, no environment and no clock; its cost is bounded by the limits in `glob`. `when` is a list of at least one condition, evaluated in listed order as an AND that stops at the first result: the first condition that is false ends the check with the `else` verdict; the first condition that errors ends it with `escalate`, reason `check_error`; if all hold the verdict is `then`. `then` is required and `else` defaults to `allow`; both are `allow`, `deny` or `escalate`. The check's `detail` is null unless it errored. A condition is `{path, op, value}`:

- `value` is required for `eq`, `ne`, `in`, `not_in`, `lt`, `le`, `gt`, `ge` and `glob`, and forbidden for `exists` and `absent` (a config error naming the key).
- `path` is dotted keys with numeric array indexes (`a.b.0.c`); key characters are `[A-Za-z0-9_-]`; a numeric segment is an index when the value is an array and a key when it is an object.
- Operators: `eq`, `ne` (JSON equality; arrays and objects compare whole; booleans never equal numbers; `value` may be JSON null to test for a present null), `in`, `not_in` (`value` is a list of scalars, null allowed; the path value must be a scalar), `lt`, `le`, `gt`, `ge` (both sides numbers, not booleans), `glob` (below), `exists` (the key is present, also when its value is null) and `absent` (the key is missing).
- A comparison operator applied to a missing path, or to a null (except `eq` and `ne` with a null `value`, and `in` and `not_in` whose list contains null: a null path value then compares as a value), or `in`, `not_in`, an ordering operator or `glob` applied to a value of the wrong type, is an error, never a quiet `false`: the check's verdict is `escalate` with reason `check_error` and its `detail` names the path and the problem (`missing`, `null`, `type` or `too large`). `eq` and `ne` between values of different JSON types are unequal, never an error. The detail is `<path>: <problem>` (for example `ci.state: missing`), where `<path>` is the configured path and `<problem>` is `missing` (the path, or a step of it, is absent or passes through a null or a scalar), `null`, `type` or `too large`; it never contains input text. An array index is canonical decimal digits without a leading zero (`0`, `7`, not `01`), at most 9 digits long; any other numeric segment on an array is missing. Only `exists` and `absent` accept a missing path. This is deliberate: a rule such as "deny when `ci.state` is not `passing`" must not allow because `ci` was absent. To make an optional field safe, put an `exists` condition first: `when: [{path: labels, op: exists}, {path: labels, op: glob, value: 'hold*'}]` is false, not an error, when `labels` is absent.
- `glob`: the path value is a string, or a list of strings of which any may match. `*` matches any run of characters except `/`, `**` any run including `/`, `?` one character except `/`; no other metacharacters; the match is anchored to the whole string and case sensitive. A pattern is a non-empty string, tokenized once when the config is loaded, and may be at most 128 characters as written (a run of three or more `*` counts as written and is then one `**`; longer is a config error). The matcher must not translate the pattern into a regular expression or backtrack: it advances the set of live pattern positions one subject character at a time (a bit set is the intended form), so its cost is at most pattern length times subject length. Limits per condition: a subject string at most 4 KiB, a list at most 256 elements, all strings together at most 16 KiB; a larger subject is an error (`escalate`, `check_error`, detail `too large`). A rule check takes no deadline and is never skipped for it ([Deadline](#deadline)). A `glob` against `labels` entries such as `pr=github.com/org/repo#3` needs `**` (`pr=**`), because `*` stops at `/`.
- There is no regex, no expression language and no code. There is no cross-field comparison, list quantifier or length; a policy that needs them uses a script check.

`validate` also reports a `then` or `else` outside the three verdicts, a missing or forbidden `value`, an empty glob pattern and a glob pattern over 128 characters.

### Agent checks

```yaml
- {name: reviewer, type: agent, instruction_file: /etc/gatectl/reviewer.md, threshold: 0.8, model: haiku}
```

An agent check asks a Claude session, run through claude-session with kind `gate-check`, to apply the policy's instruction text to the input. It is exempt from `--mode`: it is always headless (design guide section 11). An agent check may only tighten a decision.

**Keys.** Exactly one of `instruction` (a string) and `instruction_file` (an absolute path read when the check runs); and the optional `skill`, `model`, `threshold`, `timeout`, `cache_ttl`, `permission_profile`, `sandbox`, `setting_sources` and `env_allowlist`, each defaulting from the `agent:` config block. The instruction text is trusted configuration. An `instruction_file` is opened without blocking, must be a regular file of at most 64 KiB, and has its bytes hashed when the fingerprint is computed and read again when the check starts, which must give the same digest; those bytes feed the fingerprint, the cache key and `prompt.md`. An inline `instruction` that is not UTF-8 text (it contains a NUL or a lone surrogate) also escalates with `tool_missing` when the check starts. An unreadable file escalates the check with `tool_missing` when it starts; so does a file that is not UTF-8 text (invalid UTF-8 or a NUL) and one whose bytes no longer match the fingerprint's digest (it changed in between). An agent check needs no input declaration.

**Skill and plugin.** The default skill is `gatectl:gate-check`, bundled in the package's `plugin/` (a Claude Code plugin named `gatectl`, located through `importlib.resources`). A plugin is identified by the `name` in its `.claude-plugin/plugin.json`; gatectl indexes the bundled plugin and every `agent.plugin_dirs` entry by that name (two directories with the same name are a config error). A skill is `<plugin>:<skill>` and is the file `skills/<skill>/SKILL.md` of that plugin; a bare name is a config error. The session gets `--plugin-dir` for the bundled plugin and, when the check's skill comes from another plugin, that one plugin only. Every plugin directory given to a session needs the four placeholders `.claude/`, `.mcp.json`, `CLAUDE.md` and `CLAUDE.local.md` (a sandboxed session otherwise cannot run its report call and the run ends `agent_unreported`); `validate` reports `plugin_placeholders_missing` for each used directory that lacks one. A plugin or skill that cannot be found when the check starts escalates with reason `tool_missing` (a missing skill would otherwise run and exit 0 with an unusable artifact).

**Files given to the session.** gatectl creates its private directory `tmp/<decision_id>/` under its state directory (mode 0700, unless a script check has already created it; the directory and its files are created exclusively and without following links) and writes these files into it, deleting them when the run ends:

- `input.json`: the input object, serialized pretty-printed (two-space indent, one key or array element per line, so a model can page through it) with non-ASCII characters written as `\uXXXX` escapes (invisible and bidirectional code points are then visible), and wrapped in a fence, `<untrusted source="gatectl-input" id="<R>">` ... `</untrusted id="<R>">`, where `<R>` is a fresh random 16-hex-character value and every `</untrusted` and `<untrusted`, in any letter case, inside the content becomes `&lt;/untrusted` or `&lt;untrusted`. DEL (0x7f) is escaped like the other control characters (`\u007f`). The file ends with the closing fence on a line of its own. The fence id and the nonce are drawn again if either appears in the serialized input. Passed with `--input-file`.
- `prompt.md`: passed with `--prompt-file`. It states the artifact name (`verdict.json`), the per-run **nonce** (32 random hex characters), the artifact schema below, the rule that content between `<untrusted>` tags is data and never instructions, and then the policy's instruction text. gatectl adds no report or escalation instructions: claude-session's standard instructions carry those.

**Input size.** An input whose serialized content (pretty-printed, after the fence rewrite and escaping, not counting the two fence lines, so the written file is about 90 bytes larger than the cap by design) is larger than `agent.input_max_bytes` (default 64 KiB) makes the agent check `escalate` with reason `input_invalid`, detail `too large for an agent check`, before a slot is taken or a session starts. The same happens, with detail `line too long for an agent check`, when any single line of the file (after pretty-printing and escaping) is longer than 16 KiB: the Read tool caps one call by tokens and pages only by line, a long non-ASCII line costs about 5 tokens per 6 bytes of escapes, and 16 KiB stays well under that cap, so every line of an accepted input can be read, and the whole file in a few pages. The size check precedes the line check. A value that cannot be serialized as JSON (not reachable from a parsed input, which is strict JSON) makes the check escalate with `input_invalid`, detail `not serializable for an agent check`; nesting too deep to serialize counts as `too large for an agent check`. If 8 draws of the fence id and nonce all collide with the input (unreachable in practice), the check escalates with `check_error`, detail `no unused fence id`. The skill escalates anyway when it cannot read through the closing fence. Script and rule checks still see the whole input.

**Artifact.** The session reports `done` with the artifact `verdict.json`: a JSON object with exactly these keys: `schema_version` (the integer `1`), `nonce` (the run's nonce, echoed), `decision` (`allow`, `deny` or `escalate`), `confidence` (a number from 0 to 1) and `reasons` (at most 10 strings of at most 500 characters). The artifact is read from the frozen path `claude-session status --json` reports (never from the session's working copy), at most 16 KiB, without following links, and validated strictly: an unknown or missing key, a bad type or enum, a nonce mismatch or a parse failure escalates with reason `artifact_invalid`. `reasons` are untrusted. An agent check's `detail` is its artifact `reasons` joined with a semicolon and a space, and truncated to 1024 characters.

**Using the artifact.** The check's verdict is the artifact's `decision`, except that an `allow` whose `confidence` is below the `threshold` (default 0.8) becomes `escalate` with reason `low_confidence`. A `deny` or `escalate` is never loosened by any confidence. Confidence is a one-way gate, not a probability: it did not separate decisions in live runs.

**Outcome handling.** A run is a usable verdict only if `exec` exits 0 with outcome `done` and `report.implicit` false (read from the outcome object that `exec` prints and writes to `--outcome-file`, shape `claude-session/schemas/cli/outcome.json`), `status` reports a non-null artifact named `verdict.json`, and the artifact is valid. The table applies to `exec`'s exit code; a `start` or `status` that fails, times out or prints unusable JSON is `check_error`; `session_cmd` not found is `tool_missing`; a failing `forget` never changes the verdict. Anything else escalates, with the reason from this table:

| What happened | Reason |
|---|---|
| exit 14 (any end reason) | `agent_unreported` |
| exit 16 | `timeout` |
| exit 12 with end reason `sandbox_unavailable` | `sandbox_unavailable` |
| exit 12 with end reason `claude_not_found`; `session_cmd` not found; the skill or plugin not found | `tool_missing` |
| exit 0 but outcome not `done`, or `report.implicit` true, or the artifact missing, malformed or invalid, or its name, size or SHA-256 differing from what `status` reports | `artifact_invalid` |
| exit 13 (the agent reported blocked or needs-input) | `check_escalated` |
| exit 15, 17, 18, any other exit 12 end reason (including `unsafe_setting_sources`), any other non-zero exit | `check_error` |

The verdict is judged by claude-session's outcome, not by gatectl's budget: a run with exit 0, outcome `done` and a valid artifact is used even if its end reason is `timeout`. For an exit 0, `exec`'s outcome object and `status` must also agree: both report outcome `done` with exit code 0 for the run number `start` returned, and a `done` report that is not implicit whose artifact name, size and SHA-256 are the same in both; any disagreement is `artifact_invalid`. The artifact path must be absolute and contain no `.` or `..` segment, and no component of it, the file included, may be a symbolic link; claude-session reports the path already resolved (the realpath of its state directory), which is why a symlink at any component is refused. The file is opened once, must be a regular file whose size equals the size `status` reports (at most 16 KiB), and must not change while it is read. The detail of every outcome-table row other than a valid artifact is fixed text (an exit 12 is `launch refused`, followed by `: <end_reason>` only for `unsafe_setting_sources`, `sandbox_unavailable` or `claude_not_found`).

**Safety settings** are passed on every call (design guide section 11) and each has a config key replacing it:

| Setting | Passed as |
|---|---|
| `permission_profile` | `--permission-profile <file>` (the bundled file, a copy of claude-session's built-in `review` profile, or the configured absolute path) |
| `sandbox` (`required`, `preferred` or `off`) | `--sandbox <value>` verbatim |
| `setting_sources` | `--setting-sources "<comma list>"` (`""` when empty; for `gate-check` a non-empty list makes claude-session refuse the launch, `unsafe_setting_sources`, exit 12, which becomes `check_error`) |
| `env_allowlist` | `--env-allowlist-only <NAME>` per name, or `--env-allowlist-only ''` |
| `model` | `--model=<m>` when set |
| the decision's repo | `--repo=<id>` when the decision has a repo |

`validate` reports `sandbox_lowered` (a warning) for `preferred` and `off`, and `unsafe_setting_sources` (an error) for a non-empty `setting_sources`. A `model` of `null` follows Claude Code's default, so a Claude Code update can change the judge: pin `model` for a policy that matters. Callers must not pass `--hook pre-launch` selectors that match `gate-check`: a `pre-launch` hook that calls gatectl must set `exclude_kinds: [gate-check]` or it recurses until its timeout (claude-session residual risk).

**Run sequence.** One agent run is these steps, in order:

1. `session_cmd start --kind gate-check --mode headless --skill <skill> --prompt-file <f> --input-file <f> --plugin-dir <bundled> [--plugin-dir <the plugin holding the check's skill>] --timeout <n>s --label owner=gatectl --label policy=<name> --label decision=<decision_id> --label state=<tag> --actor auto:gatectl --decision-id <decision_id> --permission-profile <file> --sandbox <level> --setting-sources "" --env-allowlist-only <NAME>... [--repo=<id>] [--model=<m>] --json`. It prints `csession_id` and the run number.
2. gatectl stores `csession_id` in its slot row.
3. `session_cmd exec --session-id <id> --run <n> --outcome-file <private path> --json`. gatectl waits for it for at most the `--timeout` given in step 1 plus 10 s. If it has not returned by then: `session_cmd stop <id> --grace 2s --actor auto:gatectl`, then SIGTERM to the process group gatectl started for the `exec` child, then SIGKILL after 2 s.
4. `session_cmd status <id> --json` for the frozen artifact path, `sha256`, `size` and `sandbox_active`.
5. `session_cmd forget <id> --actor auto:gatectl --decision-id <decision_id>`, delete `input.json` and `prompt.md`, release the slot.

**Calls.** Every call is made without a shell, in the working directory `/`, with an environment built from an allowlist (`PATH` without relative entries, `HOME`, `USER`, `LOGNAME`, `LANG`, `LC_*`, `TMPDIR`, `TERM`, `XDG_*`, `CSESSION_*`, and the login variables claude-session's adopting `exec` needs: `ANTHROPIC_*`, `CLAUDE_*`, `AWS_*`, `CLOUD_ML_REGION`, `GOOGLE_*`); no `GATECTL_*` and no other variable reaches it. Its standard output is read under a byte cap and used only as strict JSON, and only closed fields of it are used (a session id `cs-` plus 8 characters, the run number, an `end_reason` token, `live`, `pending` and the labels); a `list` entry counts only when its labels include `owner=gatectl` and this decision's `decision=` label. The `--outcome-file` of step 3 is `tmp/<decision_id>/outcome.json`, deleted with the other files. When the `exec` guard expires the `stop` of step 3 is followed by SIGTERM and SIGKILL to the `exec` child's process group (the group gatectl started for it).

After a failure of any step (including a `start` that exits 12 and allocated a session) gatectl runs `session_cmd list --label decision=<decision_id> --json`, runs `stop --grace 2s --actor auto:gatectl` on every session whose run is not final (live or pending; a pending run is cancelled by `stop`, and `forget` refuses it) and then `forget`, and removes the directory and releases the slot. A failed `forget` or `stop` is left to `reconcile`. `forget` runs on every path that allocated a session.

**Reuse.** The result of an agent check is reused for an identical input: the cache key is the SHA-256 of the policy's fingerprint for the scope (it covers the policy name, `input.ignore` and every check), the agent check's name, the scope, and the hash of the input with the policy's `input.ignore` keys removed; a row is valid for the effective `cache_ttl` (default 10 minutes) and carries its own `expires_at` (its time plus that ttl); a row whose time is later than now, or whose `expires_at` has passed, is ignored. With an effective `cache_ttl` of `0` the cache is neither read nor written. Only a valid artifact from a `done` run is cached; a failure never is. Script and rule checks always run again. A reused result is marked `reused: true`, its `duration_ms` is the time spent reading the cache, it still produces its own decision with a new `decision_id` and audit line, and `--no-cache` skips the lookup but still writes the fresh result. Writing a result also deletes rows past their `expires_at` and keeps the table to 5000 rows (rows dated in the future first, then the oldest; never the row just written); as with `prune`, a row that is swept or evicted can no longer be named, so `show` reports `cache_source` as `null` for a decision that reused it.

**Slots.** At most `agent.max_parallel` (default 3) agent runs are live across all gatectl processes. A slot is a row in `state.db` (holder PID, holder process start time, boot id, decision id, `csession_id`, run start, `expires_at` = the check's deadline plus 60 s). A slot only counts against `agent.max_parallel`; it is not the liveness signal of a session or a directory (see `reconcile`). A slot is free when its holder is dead: the PID is gone or is a zombie, or its process start time or the boot id differs from the row's. The holder's start time is read after the last `)` of `/proc/<pid>/stat` on Linux (a process can name itself anything). `expires_at` is informational (`reconcile` reports an overdue live holder) and never frees a live holder. Acquiring a slot is one `BEGIN IMMEDIATE` transaction that deletes dead holders' rows and inserts the new row; it succeeds while fewer than the acquiring process's `agent.max_parallel` rows are live (there is no slot number). A slot is acquired before the agent run's files are written. Waiting follows Deadline, step 3.

**Cleanup.** After reading the artifact, gatectl copies its validated fields into `state.db`, runs `forget` (Run sequence, step 5) and deletes the run's files; the directory itself is removed when the check ends. Claude Code's own transcript under its projects directory is not removed by `forget` (Residual risks). A run that is still live when claude-session's own `--timeout` ends is finished by claude-session (exit 16); gatectl calls `stop` only on the overdue and signal paths in the run sequence.

**Probe.** `validate --probe` runs one agent check on a built-in input whose instruction asks for `allow`, with the configured safety settings, and reports exit code, end reason, `sandbox_active` and what failed. It costs one run and happens only when asked. A probe acquires a slot, generates a `gd-` id, creates `tmp/<id>/` and labels its session `decision=<id>` like any run, so a concurrent `reconcile` leaves it alone; it records no decision and no audit line. A successful probe stores `probe_ok_at` and `probe_agent_hash` in `state.db`; any failed probe, including `busy` and `budget_exhausted` and a failure before any session starts, removes any earlier pair, so the `set` hint comes back (when the removal itself fails, `failed` ends with `the earlier marker could not be removed` and the exit is still 12). The probe fails (exit 12) when it cannot start (`tool_missing`, `busy`, `budget_exhausted`), when the judged run is not a valid `allow` at or above `agent.threshold`, when `agent.sandbox` is `required` and the run did not report `sandbox_active`, and when the marker cannot be stored; its start window is `agent.timeout`, but at least `agent.min_start_budget` plus 5 s, so a configuration whose checks can start can always probe, and its deadline is that window plus the 5 s launch overhead, and `failed` is fixed text (no session or model text). The text form of `validate --probe` states the gap below. The probe runs with the `agent:` block's settings; a check that sets its own `sandbox`, `skill`, `permission_profile`, `setting_sources`, `env_allowlist` or `model` is not covered by it (an accepted gap). `validate` applies `sandbox_lowered` and `unsafe_setting_sources` to every agent check's resolved values, per-check overrides included.

## Check order

One `check` runs these steps in order:

1. **Resolve.** Parse flags and load the config (see Config for what a config error is; an unreadable config or state exits 1). An unknown policy exits 2.
2. **Read the input** from `--input <file>`, or stdin when `--input` is `-` or absent (exit 2 if absent and stdin is a TTY; a `--input` file that is missing, unreadable or not a regular file exits 2). A stdin that cannot be read (closed, a directory, not open for reading, or a read error) is an unusable input (`input_invalid`), never a usage error; `-` on a TTY is read like any stdin. A `--reason-file` and `--input` are regular files (stdin excepted) read at most the size cap plus one byte, opened without blocking. Reading stops at `input_max_bytes` + 1 bytes and when `R` reaches 0 (the reserve is kept for recording). A deadline at or below `defaults.record_reserve` (`R` is 0 or less from the start) reads no input and runs no check: the decision is `escalate`, reason `timeout`, with `checks` empty, so not even a `deny` rule can outrank it. An input over `input_max_bytes`, not a strict JSON object, or not fully read by then is **unusable**: the decision is `escalate` with reason `input_invalid` (`timeout` when the read stopped at the deadline), no check runs, and it is recorded like any decision at step 8 using the reserve. Its scope and state come from step 3.
3. **Scope and state.** The scope is `--repo` when given; otherwise the input's `repo` when it is a valid repo id; otherwise `*` when `repo` is absent or null; otherwise the scope is indeterminate (Identifiers). Apply the repo override, compute the fingerprint and the effective state (for an indeterminate scope: the strictest state over the policy's stored rows, else its initial state).
4. **`off`:** log a `check_off` event, print the `off` result and exit 0. Nothing else is evaluated: not `applies_when`, not the declaration; no check runs and no decision is recorded.
4a. **Applicability.** If `applies_when` is present, the scope is determinate and the input parsed as a JSON object, evaluate it exactly as a rule check's `when` (ordered, stopping at the first condition that is false or errors). A false condition ends the check with `allow`, reason `not_applicable`: no check runs, no decision is recorded and nothing is logged, there is no `decision_id` and no `input_sha256`, `checks` is empty, `state` is the effective state, `shadow` and `enforced` are `false`, and the exit is 0 in every state. A condition that errors, an input that is not a JSON object and an indeterminate scope all count as applicable (fail closed): the check goes on to step 5.
5. **Input declaration.** An unusable input, an indeterminate scope or a declaration mismatch skips every check: the decision is `escalate`, reason `input_invalid` (`timeout` for a read that hit the deadline), `checks` is empty, and it is recorded. When the input did not parse, the declared fields and the identity strings are null.
6. **Deterministic checks.** Script and rule checks run in their listed order. The first `deny` ends the run (later checks are `skipped`). An `escalate` does not stop later script and rule checks, which can still tighten it to `deny`.
7. **Agent checks.** They run, in listed order, only if the result so far is `allow`; once the result is `deny` or `escalate` the remaining agent checks are `skipped`. Deterministic checks always run before agent checks, whatever order the YAML lists them in. Each agent check follows the steps in Deadline.
8. **Combine and record.** The decision is the most severe verdict. The reason is the reason of the first `deny`, else of the first `escalate` in check order, else `all_passed`. Then, in one `BEGIN IMMEDIATE` transaction, gatectl re-reads the effective state, inserts the decision with that state (and the `rev` of the row that supplied it, `state_rev`), appends its audit line and commits. After the commit it prints the result, flushes it, points descriptors 0, 1 and 2 at `/dev/null` (`dup2`: a stream is never merely closed, because closing a Python stream does not close the descriptor), starts the hook supervisor and exits without waiting for it.

The state read inside the step 8 transaction decides everything that follows: the recorded `state`, the printed `state`, `shadow` and `enforced` fields and the exit code. If a `set` committed while the checks ran, the decision is recorded and answered under the new state (`shadow` to `enforced`: exit follows the decision; `enforced` to `shadow`: exit 0). If the new state is `off`, nothing is recorded (a `check_off` log event only) and the `off` result is printed with an empty `checks`. For an indeterminate scope the re-read applies the same strictest-state rule. In `shadow` and `off` a failure after the state is known never blocks (Exit codes); in `enforced` it exits 1.

**Signals.** On SIGTERM, SIGINT or SIGHUP gatectl stops what it started: it signals the process group of each running script check, kills the process group of a hook it is waiting for, signals the process group it started for its `exec` child (SIGTERM, then SIGKILL after 2 s), and runs the failure clean-up of the Run sequence (the `list` by label, `stop`, `forget`, remove the directory, release the slot) with the call timeouts above and within 10 s in total; what is left is `reconcile`'s. It writes a `terminated` log event, records no decision and exits 128 plus the signal number. A caller that timed out has already counted a veto; this only prevents leaked work.

### Deadline

One monotonic deadline starts when the process starts and covers reading the input. Its length is `--timeout` (an unsigned ASCII decimal number of seconds, with an optional fraction and exponent such as `5`, `.5`, `5.` or `1e2`, greater than 0 and at most 86400; a sign, a separator, a non-ASCII digit, whitespace, `nan`, `inf`, hex or anything out of range exits 2, also without `--dry-run`) if given, else the policy's `timeout`, else `defaults.timeout` (60 s). The repo is known only after the input is read: when a per-repo override replaces `timeout`, the deadline becomes the start plus the override's `timeout` from that moment (never earlier than now). The usable budget `R` at any moment is the deadline minus now minus `defaults.record_reserve` (default 2 s, kept for recording and output). The **launch window** of an agent run is `L = R - 5 s`; the 5 s covers `start`, `status` and `forget`.

Rule checks always run (they take no time) and are never skipped for the deadline once checks start; a rule's `deny` after a timeout still outranks it. The one exception is a deadline at or below `defaults.record_reserve`: `R` is then 0 or less before the input is read, nothing is read or evaluated (no rule either) and the decision is `escalate`, reason `timeout`, `checks` empty. `--dry-run` differs: a regular `--input` file is not deadline-bound, so the plan is still built. A script check starts only when `R` is greater than 0; its timeout is the smaller of its own `timeout` and `R`. If `R` is 0 or less when a script check would start, that check is not started: its verdict is `escalate`, reason `timeout`, detail `not started`, and every later script and agent check is `skipped`.

An agent check runs these steps in order. 1. Cache lookup: a hit needs no budget and no slot. 2. If `L` is below `agent.min_start_budget` (default 30 s), the check does not start: `escalate`, reason `budget_exhausted`. 3. Wait for a slot (poll every 250 ms); the wait ends with `escalate`, reason `busy`, when `L` falls below `agent.min_start_budget`. 4. After the slot is held, repeat step 2 and release the slot if it fails. 5. Launch with `--timeout <n>s` where `n` is the smaller of the check's timeout (agent default 300 s) and `L`, rounded up to a whole second (claude-session rejects 0).

When the budget ends while a check runs, the check in progress is stopped and the result is `escalate`, reason `timeout`, naming the check; in `shadow` the exit stays 0. Callers set the hook timeout at least 30 s above `--timeout` (for example `--timeout 540` under a 600 s hook; 28 s plus `record_reserve` is the worst case, see Bounds), so a slow check escalates instead of being killed and counted as a veto; the default hook timeout is 30 s and the default deadline is 60 s, so a hook wired without both is killed. `validate` reports `deadline_too_short` for a policy with an agent check whose effective deadline minus `record_reserve` minus 5 s is below `agent.min_start_budget` (also for `repos` overrides).

**Bounds.** Every claude-session call other than `exec` has a 5 s timeout; one that expires is abandoned (gatectl signals the process group it started for it: SIGTERM, then SIGKILL after 2 s) and counts as a failed step. `exec` is waited for at most `n + 10 s` (claude-session's own `kill_grace` after its timeout). A check normally answers before its deadline. When an agent run overruns, `start` may have taken its full 5 s before `exec` begins, and `n` is `L` rounded up to a whole second, so the `exec` guard (`n + 10 s`, with `n <= L + 1 s`) expires at most `11 s - record_reserve` after the deadline (9 s by default). The failure clean-up that follows (the `list` by label, `stop <id> --grace 2s`, SIGTERM to the `exec` child's process group and SIGKILL after 2 s, a second `stop`, `forget`) shares one budget of 10 s, as on the signal path, measured on the clock and including the 2 s SIGKILL grace of every call: each call gets the smaller of 5 s and what is left of the budget minus that grace, so the clean-up ends at most 10 s after it began. The calls that matter are kept their share: `list` also leaves 3 s (its `stop`'s 2 s grace plus 1 s) and 1 s (`forget`) and is skipped when that leaves nothing (the one known id is then stopped and forgotten, as when `list` fails); a `stop` is given at least 3 s when the budget allows (never less than its own 2 s grace, and skipped only if even that does not fit); a `forget` at least 1 s, else it is skipped. Recording follows (the lock wait is at most `record_reserve`, retried once, so at most 2 x `record_reserve`). When `exec` itself overruns, the worst case with every call at its limit is therefore the deadline plus 21 s plus `record_reserve` (23 s by default). The worst chain is a hostile one: `exec` returns in the last second of its guard (`11 s - record_reserve` after the deadline), `status` hangs and ignores SIGTERM (5 s plus the 2 s grace, outside the clean-up budget), the clean-up of the failed step then takes its 10 s, and recording follows: the deadline plus 28 s plus `record_reserve` (30 s by default). On the success path `forget` is outside the clean-up budget too (5 s plus 2 s), which keeps that chain shorter. A step that could not finish is left to `reconcile`. Callers must set the hook's own timeout at least 30 s above `--timeout`, which holds exactly for the default `record_reserve` of 2 s and no more; with a larger `defaults.record_reserve` the margin is 28 s plus that value, so a caller should leave slack above it.

## Reasons

`reason` is a closed list. The policy's `reason` and each check's `reason` come from it; free text goes only in a check's `detail`.

| Reason | Meaning |
|---|---|
| `all_passed` | every check allowed |
| `check_denied` | a check denied |
| `check_escalated` | a check escalated by its own verdict |
| `input_invalid` | the input is missing a declared key, has the wrong type, is too large, is not a strict JSON object or has an unusable `repo`, has declared fields over 32 KiB (ASCII-escaped canonical JSON), or is too large for an agent check |
| `timeout` | a check ran out of its time, or the input read did |
| `budget_exhausted` | too little of the deadline was left to start an agent check |
| `busy` | no agent slot became free within the budget |
| `tool_missing` | `claude-session`, the skill, the plugin, an `instruction_file` or a script executable could not be found or read (its `detail` names the missing command and, for `claude-session`, the install command `uv tool install git+https://github.com/agent-workflow-kit/claude-session`) |
| `agent_unreported` | the agent run ended without a report |
| `artifact_invalid` | the agent's artifact is missing or fails validation |
| `low_confidence` | the agent allowed below the threshold |
| `sandbox_unavailable` | the required sandbox could not start |
| `check_error` | a check crashed, was killed, printed contradictory output, or hit a rule type error |
| `not_applicable` | the policy's `applies_when` is false; nothing ran (never an authorization) |

## Outcomes

After the fact, someone says whether a decision was right: `gatectl outcome <decision-id> agree|disagree [--signal S] [--reason-file F]`.

| Decision | `agree` means | `disagree` means | Counts as |
|---|---|---|---|
| `allow` | it was right to allow | it should not have been allowed | unsafe miss |
| `deny` | blocking was right | it should have been allowed | over-strict miss |
| `escalate` | a human was needed | it could have been decided automatically | over-strict miss |

- Outcomes are append-only: each is a record with its actor, signal and optional untrusted reason. A decision made while the policy was `off` does not exist, so it has none, and neither does a `not_applicable` answer. Outcomes are ordered by their insertion sequence number, not by their clock (equal or stepped-back timestamps cannot reorder them). Every `outcome` call appends one record; `changed` is true when the decision's effective outcome changed. A reason is read to at most 1 KiB (`--reason-file -` waits at most 10 s for stdin) and a longer one is truncated with a final `…`. An id that is unknown or was pruned exits 10 (`not_found`, message "unknown or pruned id; see audit.jsonl"). An outcome that is an unsafe miss on an enforced decision of a policy that is no longer configured is recorded and counted but never changes a state (a `drop_skipped` log event). A reason file that is unreadable, or stdin still open after 10 s, exits 2 and records nothing, as `set` does; the reason is read before the id is looked up, so a usage error precedes a `not_found`.
- **Effective outcome** of a decision: read its outcome records in sequence order. A `disagree` from any actor sets it to `disagree`. An `agree` from a `human:*` actor sets it to `agree`. An `agree` from any other actor is recorded and shown but never changes it. No outcome yet is `pending`. So an automatic `agree` can neither inflate a record nor cancel a `disagree`; only a later human outcome supersedes one.
- `--signal` defaults to `human` for a human actor and `auto` otherwise. A late failure source (a revert, an incident) files `outcome <id> disagree --signal revert`; gatectl knows no sources of its own. Callers find the decision by the id they stored, or with `decisions --policy P --object-id X`. Gates wired as hooks file no outcomes themselves. Whoever operates the gate files them, within the rules above: a human files `agree` (at a TTY, or a tool relaying the human's own action with `--actor human:<name>`, as review-watch does when you accept or reject a draft), and automation (a cron job, a harness rule) files `disagree` for a revert or an incident. An automatic `agree` is recorded and never counts, so a gate that only automation operates builds no record until a human files its outcomes, for example in a batch from `decisions --outcome pending --json`; see the README wiring checklist.
- **Automatic drop to shadow.** When an outcome makes a decision's effective outcome `disagree` (from `agree` or `pending`) and that decision was an `allow` recorded in state `enforced`, and the row that gave the decision its state (its `state_rev`, recorded on the decision) is still the effective state row of the decision's scope (the repo row, else the `*` row), gatectl writes a `shadow` row for the decision's scope (the repo, or `*`: a decision with no repo drops the `*` row, which drops every repo that inherits it), appends a `state_change` audit record with cause `miss` whose `result.triggered_by` is the decision's id, all in the transaction that recorded the outcome, then fires `post-state-change` after the commit. A different effective row (a re-enforcement, a repo row written since, a drop already done) means the miss belongs to an earlier enforcement: it is counted and nothing else happens (a `drop_skipped` log event). A decision with no `state_rev` (its state came from an indeterminate scope) never drops either: the miss is counted and a `drop_skipped` log event is written. Other repos keep their state. An over-strict miss, or a miss on a `shadow` decision, only counts in the record. The outcome result's `miss` is non-null only when this outcome record changed the effective outcome to `disagree` (so a second `disagree` on an already `disagree` decision has `miss: null`).

### Track records and recommendation

`stats` builds one record per policy, repo (or none) and fingerprint: decisions by verdict, outcomes by effective outcome, unsafe and over-strict misses, counts by signal and by actor kind, and per-reason counts with the time each was last seen. Shadow and enforced decisions both count. Records are keyed by the decision's scope and are not pooled across repos. `actor_kinds`: `human` is a `human:*` actor, `automatic` an `auto:*` actor, `unattributed` the actor `auto:unknown`. `signals` and `actor_kinds` count outcome records (not effective outcomes). `reason_counts` count check entries by their reason (a decision with two failing checks counts twice) with the last time each was seen; a decision none of whose entries has a reason (an all-allow decision, or one with no entries such as `input_invalid`) counts once under its own decision reason, so `all_passed` is counted. Records are ordered by policy, then scope (`*` first), then fingerprint; `reason_counts` by reason; `signals` by name. `--since` selects decisions by decision time, with all their outcomes.

The recommendation uses unsafe misses only. A **case** is the set of decisions of one record that share a `case_key`, a SHA-256 computed when the decision is recorded: of the canonical JSON of the list `[object_type, object_id, declared values]`, with the keys listed in `input.ignore` left out of the declared values, taken from the validated input before capping, or, when `object_id` is null, the SHA-256 of the canonical serialization of the input with the policy's `input.ignore` keys removed (the same hash the cache key uses; so a retry of the same input is one case, and different inputs are different cases). A harness that polls an object should send `object_type` and `object_id`. `n` is the number of cases that have at least one resolved `allow` decision (effective outcome `agree` or `disagree`), and `k` is the number of those cases in which any resolved `allow` has effective outcome `disagree`; so retries and polling of one object count once. `unsafe_misses` and `over_strict_misses` count decisions (an `allow` with effective outcome `disagree`; a `deny` or `escalate` with `disagree`); `unsafe_miss_cases` is `k`, the number of cases with at least one unsafe miss; `resolved_decisions` is the raw count of resolved `allow` decisions and `resolved_allows` is `n`. `upper_bound` is the one-sided Clopper-Pearson upper bound `U` at `recommend.confidence` (default 0.95): `U` solves `P(X <= k | n, U) = 1 - confidence`, `U = 1` when `k = n`, `U = 1` when `n = 0`; computed by bisection to a tolerance of 1e-9 (the upper end of the bracket, so it is never below the true bound by more than float noise; a bound within 1e-9 of `max_miss_rate` may therefore read `not_yet`) and printed rounded **up** to 6 decimals (after discounting the bisection tolerance, so 0.95 prints as 0.95 and a bound of 3e-7 prints as 0.000001, never 0); the recommendation compares the unrounded value. `recommend` is `enforce` when the scope is not `enforced` and `U <= recommend.max_miss_rate` (a bound of 1, that is `n = 0` or `k = n`, never holds, even with `max_miss_rate: 1`, so such a record is `not_yet`, or `reconsider` when enforced) (default 0.05; with `k = 0` that takes 59 cases, 58 give 0.0503), `not_yet` otherwise, `keep` when `enforced` and `U` holds, `reconsider` when `enforced` and it does not. It is advisory: gatectl never enforces by itself. With `--since`, or for a record whose fingerprint is not the current one for its scope, `recommend` is `null`; the record carries `current: true|false`.

## State changes

`gatectl set <policy> off|shadow|enforced [--repo ID] [--all] [--reason-file F]` writes the state row of exactly one scope (`*` without `--repo`; `--repo '*'` names it too; `--all` together with `--repo` exits 2). `previous_state` is the scope's effective state before the call. A stored row is **equal** to the request when its state matches and, for `enforced`, its fingerprint is the current fingerprint of the row's own scope. An equal row is a no-op (exit 0, `changed: false`, no audit record). Every other call writes the row and has `changed: true`: a row that was absent counts (an explicit row pins the scope even when the effective state does not change), and so does a human `set ... enforced` on an enforced row with a stale fingerprint, which **re-enforces** it: new fingerprint, `set_by`, `set_at` and `rev`, an audit `state_change` whose `previous_state` equals `state`, and no `post-state-change` hook (the state did not change). This is how an operator accepts an edit; a gatectl upgrade that changes the bundled plugin is accepted the same way. Setting `enforced` is a human action (Actors and human actions); any other attempt exits 20 with reason `human_required` and writes a `warning` log event (no audit record: nothing changed). A human may enforce without a recommendation. `shadow` and `off` are open to any actor so that automation can always fail safe: they remove an automatic action's authority. For a gate wired as a veto they also remove the veto, which is a loosening (Residual risks). A global `set` never rewrites a repo row. `--all` is accepted only with `off` or `shadow` (otherwise exit 2): it writes the `*` row and every stored row of the policy in one transaction and audits one `state_change` per scope that changed; the result's `scope` is `*`, `previous_state` and `state` are those of scope `*`, `changed` is true when any scope changed and `scopes_changed` lists the scopes that changed. A policy with no rows at all gets the `*` row. There is no command that deletes a row: after an automatic drop to `shadow`, `set <policy> enforced --repo X` re-enforces X, and a repo row set to `shadow` stays until set again. `set` is audited with its actor and reason; the effective state of every other scope is untouched. A row written for a scope whose definition cannot be computed (a policy only in `state.db`, or a configured policy or override that does not validate; `off` and `shadow` only) stores the fixed marker fingerprint `sha256:` plus 64 zeros; no comparison ever uses the fingerprint of a row that is not `enforced`. A policy that is not in the config, or does not validate, counts as `shadow` for a scope with no row (`previous_state`). The reason is read as at most 1 KiB (longer is cut), sanitized and stored in the audit line only; an unreadable reason file, or a stdin still open after 10 s, exits 2 and changes nothing. A `--reason-file` that is a symlink is followed and the file it resolves to must be a regular file; it is read with the caller's own privilege, so it can name any file the caller can read (its first 1 KiB is stored in the audit line). A closed stdin at launch reads as empty. `--all` appends its audit lines with one write after every row is written, and exits 1 without changing anything when the policy has more than 10000 stored rows to list them all. The human check runs before the config or the reason is read.

Every state row stores the fingerprint of its own scope's effective definition at the time the row was written (the `*` row with the policy's global definition, a repo row with that repo's effective definition; for an automatic drop, the decision's fingerprint) and a **revision** `rev`, taken from a store-wide counter that increases with every row write. When the scope's effective state is `enforced` and the row that supplies it has a fingerprint different from the current fingerprint of that row's own scope, `check` adds the warning `definition_changed` to its result and `policies` shows `definition_changed: true` for that row; the state does not change. A repo that has its own override and inherits an enforced `*` row is not compared with its own definition (the `*` row is compared with the global one): the override inherits the enforcement and has an empty track record; `set <policy> shadow --repo X` holds it until the record matures. A decision records the `rev` of the row that supplied its state as `state_rev` (null when the state came from the config's initial state or from an indeterminate scope).

`set ... enforced` prints a hint, never blocks: (1) when the policy has an agent check and no `validate --probe` has succeeded for the current agent configuration (`state.db` `meta` keys `probe_ok_at` and `probe_agent_hash`; the value is `sha256:<hex>` over the canonical JSON of `{agent: the validated agent: block with defaults filled, session_cmd: the resolved command (null when unresolved), version: the gatectl version}`, computed by `agenthash.agent_config_hash`, which `validate --probe` must use when it stores the key), a hint to run it; (2) when the policy has no script or rule check, a hint that no deterministic check backs an automatic action; (3) when `--repo` names a repo for which this policy has no recorded decision, a hint that the repo spelling matches nothing seen yet (a typo such as `Org/Repo` would enforce a scope no caller uses). The `set` result's `hint` is the hints joined by a space, or null.

## Commands

All commands take `--json`, `--config PATH`, `--verbose`, `--quiet`, `--actor` and a repeatable `--decision-id` (Global flags). `--version` prints `gatectl <version>`. `--repo` accepts `*` for scope `*` in `decisions`, `stats`, `policies` and `set`.

### `check`

`gatectl check <policy> [--input <file> | --input -] [--timeout <seconds>] [--repo <id>] [--no-cache] [--dry-run] [--actor A]`. Evaluates the policy (Check order) and prints the check result on stdout as JSON, always, whatever `--json` says; longer human-readable text goes to stderr only on a TTY. Exits 1, 2, 11 and 13 also write exactly one sanitized line to stderr, on a TTY or not, at most 512 characters, built only from closed fields. For exits 11 and 13 it is `gatectl: <decision> <policy>@<scope>: <reason> (<check name>) <decision_id>` (the decision grammar, the policy and scope grammars, a reason code, a configured check name, the decision id); the parenthesized `(<check name>)` group is left out when no check supplied the reason (an unusable input, an indeterminate scope, a declaration mismatch or a read that hit the deadline); for exits 1 and 2 it is `gatectl: <error code> <policy>` with the policy name when known. A hook caller reports this line as the veto or escalation reason. A shadow failure (exit 0 with `error`) writes one warning line, `gatectl: warning shadow_failure <policy>@<scope>`, unless `--quiet`. `--dry-run` loads and validates the policy, the declaration and the input, prints the resolved plan (policy, scope, effective state, fingerprint, each check with its resolved argv or skill, and what would be skipped) and runs nothing and records nothing. A dry run of an input that fails the declaration prints the plan with `input_valid: false` and exits 0. In state `off`, or when `applies_when` is false, the plan shows every check with `would_run: false`. `input_valid` is `true` under state `off` and under a false `applies_when` (the declaration is not evaluated before steps 4 and 4a), and `false`, with every `would_run` false, for an indeterminate scope, an unusable input, a declaration mismatch or a value that cannot be recorded. In a dry run `--timeout` and the policy's `timeout` bound only the read of stdin, to the deadline minus `record_reserve` but at least 0.5 s; a regular `--input` file is not deadline-bound. The `argv` elements of the plan are for display only: unprintable characters are replaced by U+FFFD and an element over 1024 characters is cut to 1023 followed by `…`, so they are not byte-exact. A dry run reads the stored state (read-only): it never creates a row or a database, and it exits 1 when the state is unknown (see Exit codes). A reader of a WAL database may leave empty `state.db-wal` and `state.db-shm` files (private, mode 0600). The plan shape is `schemas/cli/check-dry-run.json`. `--actor` is recorded with the decision.

### `outcome`

`gatectl outcome <decision-id> agree|disagree [--signal S] [--reason-file F|-]`. Records an outcome (Outcomes). The reason is untrusted, at most 1 KiB (longer is truncated); `--reason-file -` reads at most 1 KiB + 1 byte and waits at most 10 s. An unreadable reason file, or stdin still open after 10 s, exits 2 and changes nothing; the reason is read before the id is looked up.

### `decisions`

`gatectl decisions [--since T] [--policy P] [--repo R] [--object-id X] [--outcome pending|agree|disagree] [--decision allow|deny|escalate] [--declared key=value] [--limit N]`. Lists decisions, newest first (default limit 100), with their effective outcome. Rows carry `declared`, `input_sha256`, `decision`, `state`, `tool`, `hook`, `actor`, `fingerprint`, `state_rev`, `case_key` and the effective outcome. `--outcome` filters by the effective outcome, `--decision` by the verdict, `--declared` by an exact match on a declared string, and `--repo '*'` selects scope `*`. `--limit` is an integer from 1 to 1000 (anything else exits 2), and `truncated` is true when more rows matched. `--since` selects by decision time, inclusive. `--policy` must be a configured policy or one in `state.db` (unknown: exit 2, `details.kind: unknown_policy`). `--object-id` and `--declared key=value` (each part at most 256 characters; the first `=` splits) match the stored, sanitized text exactly: a `%` or `_` is an ordinary character, and `--declared` matches string values only. The text form is one sanitized line per decision (`no decisions` when there are none, a last line when truncated). The reader never writes: with no `state.db` and no audit history the list is empty and nothing is created; with an audit history and no usable `state.db` it exits 1 with `state_db_missing` (Exit codes). It loads the config (to mark decisions of removed policies `configured: false`), so a config that cannot be loaded exits 2 as for every command that loads it. A row whose stored values break the schemas' closed lists (an id, a time, a state, a reason code, an actor, a fingerprint), or whose `declared_json` holds an object with a duplicate key, makes the command exit 1 with the fixed text `state.db holds an invalid decision row`; a NUL byte in a stored value is never cut away by the reader (in a closed-list column it is a tamper, in free text it becomes the replacement character); free text is sanitized and cut to its cap.

### `show`

`gatectl show <decision-id>`. One decision in full: every check's result and detail, the declared fields, the cache source, the outcome history, the effective outcome and the recorded input hash. The id is a full id or a unique prefix (Identifiers). `cache_source` names the decision whose agent result a reused check read: the decision of the `agent_cache` row the check named, accepted only if that row already existed and was not yet expired at the shown decision's time (`null` when no check reused one, the row is gone or expired, or it was replaced after the decision by a refresh of the same key). Residual limit: the cache keeps one row per key, so once a key is refreshed the earlier producer can no longer be named and the answer is `null`, never a later decision. The outcome history lists at most 1000 records in sequence order; `effective_outcome` is computed over all of them. The text form is sanitized lines. Like `decisions`, `show` never writes, loads the config (a config that cannot be loaded exits 2), exits 1 with `state_db_missing` when an audit history has no usable `state.db`, and refuses a tampered row with exit 1. It reads the decision, its cache source and its outcomes in one read transaction, so a concurrent `prune` or outcome cannot make them disagree; a decision that is gone before that read exits 10.

### `stats`

`gatectl stats [--policy P] [--repo R] [--since T]`. Track records and recommendations (Track records and recommendation).

`stats` is read-only: it creates, migrates and writes nothing. With no `state.db` and no audit history there are no records (text `no records`, JSON `records: []`); a missing `state.db` with audit history exits 1 with `state_db_missing`. A config that cannot be loaded exits 2. A stored decision or outcome that does not follow its grammar (an invalid time, key, case key, `checks_json`, reason, signal or actor kind, or an outcome other than `agree` or `disagree`) exits 1 with the fixed text `state.db holds an invalid decision row`, never printing the value. The text form prints one block per record; a record whose policy is not configured is marked `(policy removed)` and one whose fingerprint is not the current one `(old)`. `upper_bound` is rounded up as described under Track records and recommendation. In `reason_counts`, a decision none of whose check entries has a reason is counted once under its own decision reason (so `all_passed` appears), where an entry with a `null` reason does not count on its own.

### `set`

`gatectl set <policy> off|shadow|enforced [--repo ID] [--all] [--reason-file F]` (State changes). `set <policy> off --all` is the kill switch. `--reason-file -` reads at most 1 KiB + 1 byte and waits at most 10 s.

### `policies`

`gatectl policies [--repo ID]`. Like `stats`, it exits 1 with `state.db holds an invalid decision row` when a decision row it reads for the records does not follow its grammar (only the rows of the shown policy and scope are checked). Every policy with its initial state, its stored scope rows (state, who set it, when, cause, the fingerprint it was set for, its revision `rev`, `definition_changed`), the effective state for the given repo (or `*`), its fingerprint, a summary of each check and the recommendation of each record. With `--repo` it shows that repo's effective definition. The text form marks a policy defined by that repo's override with `(override)`; the JSON has no such member (the fingerprint and checks differ). A policy, or its override for the scope, that is invalid is left out of the list and one stderr line `gatectl: warning config_problem: ...` says so (`validate` lists the problem); `--quiet` silences that line. A summary is one sanitized line of at most 512 characters: the argv of a script check (elements that need it shell-quoted, so `a b` and `a` `b` differ), the conditions of a rule check (values as JSON) followed by the words `then <x> else <y>`, or `skill <plugin>:<skill>` of an agent check. Checks are listed in execution order. `scopes` lists every stored row of the policy (by scope; read-only: with no audit history a missing `state.db` means none, with a history it exits 1 with `state_db_missing`; a row whose `set_by`, `set_at` or `fingerprint` does not follow its schema exits 1 with the fixed text `state.db holds an invalid state row`, never printing it). `effective_state` is the shown scope's own row, else the `*` row, else the initial state; `effective_cause` and `effective_set_at` are the `cause` and `set_at` of the row that decides it (`null` for the initial state), so a consumer can tell an automatic drop (`miss`) from an operator's `set` with one equality on a flat field. These flat members describe the stored row that decides the shown scope only (the `*` row when `--repo` is not given); an automatic drop of a repo-scoped row is visible only in `scopes`. `definition_changed` is true only for an `enforced` row whose fingerprint differs from the current fingerprint of the row's own scope (an `enforced` row that carries the marker below, or whose scope's definition cannot be computed, counts as changed), and never for another state. A row written for a scope with no definition stores the marker fingerprint (State changes); it is shown as `fingerprint: null` (the member is nullable), never as a fingerprint. `records` holds the records `stats` builds for the shown scope (the `--repo` scope, else `*`) and for this policy, one per fingerprint, in the `stats` order, each with its recommendation. The result gained `effective_cause` and `effective_set_at` (both required, nullable) and a nullable `scopes[].fingerprint`; the schema is closed, so this is an interface change of `policies.json`, not an additive one, and a consumer of the earlier shape must be updated.

### `validate`

`gatectl validate [--probe]`. Lints the config without running a check: the whole file and each policy and override eagerly, including resolution of binaries, files, skills and plugins. Exit 0 when valid, 2 when not, printing each problem as `{code, path, message}` and each warning in the same shape. Problem codes: `unknown_key`, `invalid_value`, `invalid_rule`, `glob_too_long`, `unresolved_argv0`, `skill_not_found`, `plugin_not_found`, `plugin_placeholders_missing`, `instruction_file_unreadable`, `override_unknown_policy`, `override_unknown_key`, `bare_skill_name`, `unsafe_setting_sources`, `deadline_too_short`, `session_cmd_unresolved` (a problem when some policy or override has an agent check, a warning otherwise) and `state_db_missing` (`validate` is read-only, except that `validate --probe` writes `state.db` and its two `meta` rows (creating the database when it is absent and no audit history exists; with history and no database, `validate` already reports `state_db_missing` before any probe), and reports it in the states where `check` gives `state_db_missing`: `audit.jsonl` is anything but an empty regular file (a FIFO, directory or symlink counts as history) and `state.db` is missing, zero-length with no live WAL, or has no `meta.schema_version` row (a SQLite file with no tables or with no such row); plus one addition: a non-empty foreign or junk `state.db` (not SQLite's header, or tables but no `meta.schema_version` row) with no history, which `check` refuses with a plain exit 1 (the code is reused because a new one needs a schema change). `validate` is silent where `check` refuses without that reason: `schema_newer`, a damaged or busy database, an unusable `schema_version` value, a `meta` table with other columns, a `state.db` that is a symlink, FIFO, directory or not owned by the user, a state directory that is a symlink, not a directory or not owned by the user, and any permission problem (`check` repairs a mode, `validate` cannot). A `state.db` with frames in its `-wal` is never opened, because reading it would write the `-shm` file: it is judged from its header only (a non-empty file that does not start with SQLite's header is junk whatever its WAL holds; a zero-length file with a live WAL is not judged). A fresh install, with no history yet, is valid and has no `state.db` until the first `check` or `validate --probe`). A malformed `applies_when`, or `when`, `then` or `else` of a rule check (wrong shape, empty list, bad path, op or value) is `invalid_rule`, at the offending path (`applies_when` or `when` itself for an empty or non-list value), but an unknown key inside a condition stays `unknown_key` (`override_unknown_key` in an override); a glob over the length limit is `glob_too_long`; every other malformed value, range violations included, stays `invalid_value`. Warning codes (they never make the config invalid): `relative_argv`, `sandbox_lowered`, `orphan_state` (a policy in `state.db` that is not in the config), `agent_only_policy` (a policy with no script or rule check) and `session_cmd_unresolved` (when no policy or override has an agent check). `--probe` also runs the probe (Agent checks) and exits 12 when it fails. A config file that cannot be parsed is reported as one `invalid_value` problem at path `config` (exit 2); an unreadable one exits 1. The text form ends with one trailer line: `invalid` when there are problems, `probe failed` when a probe ran and failed (exit 12), otherwise `valid`. The text form prints the resolved `session_cmd` path (`session_cmd: <path>` or `session_cmd: not found`); the JSON result has no such member. At most 500 problems and 500 warnings are listed. No config value is ever echoed, except the sanitized resolved `session_cmd` path in the text form: messages are fixed text and paths hold keys only.

### `export`

`gatectl export [--log] [--since T]`. Prints `audit.jsonl` (default) or `log.jsonl` records as JSON lines; `--since` filters by the record's `ts`. A record is a UTF-8 JSON object with a `ts`; a blank line (empty or only whitespace) is skipped silently and not counted; a line that is not a record (not JSON, not an object, no valid `ts`, over 64 KiB, a number that does not serialize) is skipped and counted, and `gatectl: warning export: N lines skipped (not valid records)` goes to stderr after the output (`--quiet` does not silence it). `--since` keeps the records whose `ts` is not older than T. Output is the parsed record as compact ASCII JSON with every string sanitized, one line per record, in file order. `export` streams (memory is bounded by one line), reads only the bytes the file held when it was opened, never creates, locks or writes anything, and refuses (exit 1) a file that is not a regular file owned by the user; a missing file is an empty export. A closed stdout or pipe (`EPIPE`, `EBADF`) ends it quietly with exit 0; any other write failure (a full disk, `> /dev/full`) stops it, prints `gatectl: internal: cannot write to stdout` to stderr and exits 1.

### `reconcile`

`gatectl reconcile [--dry-run]`. Takes the `reconcile` lease (below), then: frees slot rows whose holder is dead; removes every `tmp/*` directory whose `owner` file names a process that is not alive (a directory with no readable `owner` file counts as dead 10 minutes after it was created); deletes cache rows past their expiry; and, when `session_cmd` resolves (Config), lists sessions labeled `owner=gatectl` and `state=<tag>` (`session_cmd list --label owner=gatectl --label state=<tag> --json`) and, for each whose `decision=<id>` label matches the decision id grammar (`gd-` and 12 base32 characters; a session with any other value is left alone, neither stopped nor forgotten) and has no `tmp/<id>/` directory with a live owner (the path is derived only from that validated id, and the directory's realpath must lie inside the state directory's `tmp/`), runs `stop --grace 2s` on every run that is not final (live or pending) and then `forget`; as `reconcile` is not bound by a check deadline, its `stop` call has a 15 s timeout (the 2 s grace, the SIGKILL and the wait for the final run), so a stubborn session is killed and not abandoned. A session sweep that cannot run because `session_cmd` does not resolve is skipped with `sessions_checked: false` and exit 0, so a standalone install loses nothing under cron; a `list` that fails ends the sweep, with `sessions_checked: false` and exit 12. Reports counts (`slots_freed`, `sessions_stopped`, `sessions_forgotten`, `tmp_removed`, `cache_expired`), `overdue` (live holders past `expires_at`; never freed) and `overdue_holders` (`{decision_id, pid}` of each, so an operator can `kill -9` that exact PID). Passes `--actor auto:gatectl` to `stop` and `forget`. A label value is compared as a string and never used to build a path; the only path built is `tmp/<id>` from an id that passed the grammar. Safe to run at any time and under cron. `--dry-run` reports what it would do and changes nothing.

### `prune`

`gatectl prune [--older-than D] [--dry-run]`. Deletes decisions, with their outcomes, older than `D` (by decision time) from `state.db`, except current decisions, and deletes cache rows past their `expires_at` whatever `D` is. (An agent check's cache write sweeps the same expired rows and bounds the table at 5000 rows, so `show`'s `cache_source` for a reused decision is `null` once its row is gone, whichever swept it.) A decision is **current** when its fingerprint equals the current effective fingerprint of its scope for a configured policy: the repo's override fingerprint when an override for that repo exists, else the global definition's (so the live track record of an ordinary repo is kept); a policy that is no longer configured has no current decisions. A policy whose fingerprint computation hit the `unreadable` marker is skipped entirely and listed in `skipped_policies`, so a transient read failure never makes live records look old. Deletion runs in batches of at most 500 rows per transaction; `prune` never runs `VACUUM` and checkpoints the WAL with `PASSIVE`, so it cannot hold the write lock longer than `record_reserve`. `audit.jsonl` and `log.jsonl` are never pruned. Without `--older-than` it uses `retention.older_than`; when that is `null` it deletes no decisions (expired cache rows are still deleted). The result is `{dry_run, deleted, older_than, kept_current, skipped_policies, already_running}`: `deleted` counts the decisions, outcomes and cache rows and `kept_current` the decisions kept because they are current. `prune` is audited when a non-dry-run call deleted any row; `inputs.older_than` is null when only cache rows were deleted; dry runs are not audited.

**Maintenance lease.** `reconcile` and `prune` each take a lease before doing anything: a `meta` row `lease:<command>` holding the holder's PID, start time and boot id, written in one `BEGIN IMMEDIATE` transaction; a lease whose holder is dead is taken over at once. A second caller that finds a live holder exits 0 with `already_running: true` and does nothing (the counts are 0 and, for `reconcile`, `sessions_checked` is `false`). The lease is released when the command ends.

### `cron`

`gatectl cron install|uninstall [--dry-run]`. Writes or removes one block in the user's crontab, between the lines `# gatectl managed` and `# gatectl managed end`: an explicit `PATH=<home>/.local/bin:/usr/local/bin:/usr/bin:/bin` (`<home>` expanded at install time), a line `XDG_STATE_HOME=<value>` only when that variable was set when the command ran, then `*/15 * * * * gatectl reconcile --quiet` and `17 3 * * * gatectl prune --quiet`, in that order (`prune` still deletes expired cache rows while `retention.older_than` is null). `install` always writes both lines and replaces an existing block, so `awkit cron install` and `gatectl cron install` produce the same block and can run in any order. `--dry-run` reports the lines and changes nothing. `cron` writes a `cron` log event.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | `check`: allow, or any result in `shadow` or `off`; other commands: success |
| 1 | internal error; `check` also uses it when the policy's state is unknown (config or database unreadable, or `state.db` missing, or present with no `meta.schema_version` row (an empty or schema-less file, or one SQLite reports as not a database (`file is not a database`: an invalid or damaged header); corruption beyond the header stays a plain exit 1), while `audit.jsonl` in the same directory is not empty: `state_db_missing`; gatectl never creates a new database over an existing history; restore the database, or move `audit.jsonl` aside on purpose; `policies`, `decisions` and `show` open `state.db` the same way and exit 1 with `state_db_missing` in the same state, while with no history a missing `state.db` is an empty store for them) and for any internal failure while the state is `enforced` |
| 2 | usage error: bad flags, an unknown policy, a config error, a bad `--timeout`, no `--input` with a TTY stdin |
| 10 | not found: a decision id |
| 11 | `check` in `enforced`: deny |
| 12 | the requested operation failed for an expected reason (`validate --probe` failed) |
| 13 | `check` in `enforced`: escalate |
| 20 | refused: `set ... enforced` without a human (`human_required`) |
| 21 | ambiguous decision-id prefix |

There are no tool-specific codes above 22; a process stopped by a signal exits 128 plus the signal number (Check order, Signals). In `shadow` and `off`, gatectl never exits with anything but 0 for a decision it could evaluate: when the state is known to be `shadow` or `off` and a later step fails (for example the decision cannot be written), `check` exits 0 with no `decision_id` key, the would-be `decision` and `reason` kept, an `error` object and a warning on stderr, because nothing may rely on a shadow result. `BEGIN IMMEDIATE` waits at most `defaults.record_reserve` (default 2 s) for the write lock; a reader never takes the write lock and never blocks on a writer in the steady state (WAL; it retries transient busy-class errors for at most about 2 s). A lock timeout in step 8 is a failure after the state is known: exit 0 with `error` in `shadow`, exit 1 in `enforced`, and the check retries the transaction once before failing. `state.db-wal` and `state.db-shm` are part of the database: do not remove them by hand.

## Output by exit code

- **`check`** exits 0, 11 and 13 print the check result. Exits 1 and 2 print the error envelope. A `--dry-run` prints the plan.
- **Other commands** print their result object on exit 0 and the error envelope otherwise. `validate` exit 2 and `--probe` exit 12 print the problem list or probe report.

`decision_id` and `input_sha256` are present exactly when a decision was recorded. In state `off` the result has `decision: null` and no `decision_id` key. In a shadow failure the result keeps the would-be `decision` and `reason` and has no `decision_id` key and a non-null `error`. For `not_applicable` the result has `decision: allow`, reason `not_applicable`, the effective `state`, `shadow: false`, `enforced: false`, no `decision_id` key, no `input_sha256` key and `checks: []`. A caller reads an absent `decision_id` as null. (Callers that read a hook's stdout, such as claude-session and forgectl, accept `decision_id` only as a string or list and warn on anything else, so gatectl never prints a null one.) `shadow` and `enforced` are true only for an evaluated answer in that state (never for `not_applicable`). `state` is the effective state read when the decision was recorded. A check's `reason` is `null` when it allowed; `confidence` and `reused` appear on agent checks only. `input_sha256` identifies exactly what was evaluated; the declared field values are in `show`. `warnings` holds the closed codes `repo_invalid`, `repo_mismatch`, `definition_changed`, `config_problem` (another policy in the config is invalid, or, for a command that runs no check, a shared key is invalid; `validate` lists it) and `output_truncated` (a script's stdout or stderr passed 64 KiB). No input text is printed, only the declared fields' values in the recorded decision (shown by `show`), never in this result. stdout carries only this object, so a hook caller that reads a hook's stdout finds `decision_id`.

### Other results

`outcome`: `{decision_id, outcome, signal, actor, changed, effective_outcome, miss: null|"unsafe"|"over_strict", state_change: null|{policy, scope, state, cause}}`. `set`: `{policy, scope, state, previous_state, changed, scopes_changed, hint}`. `decisions`: `{decisions: [...], truncated}`. `show`, `stats`, `policies`, `validate`, `export` (JSON lines), `reconcile`, `prune`, `cron`: their documented shapes in `schemas/cli/`.

### Error envelope

`{"error": {"code": "...", "message": "...", "reason": "...", "details": {...}}}`. `code` is one of `usage` (2), `config_invalid` (2), `not_found` (10), `ambiguous` (21), `refused` (20, with `reason`), `failed` (12) and `internal` (1). Messages name the offending key or id. `reason` is `human_required` for `refused`, and `schema_newer` or `state_db_missing` for `internal`.

## Hooks

gatectl is the gate, so it has no `pre-` hooks. It fires three post hooks, configured under `hooks:` with `cmd`, `timeout` (default 30 s) and `async`. A hook receives its payload on stdin from `tmp/hook-<random>/payload.json` (mode 0600; the supervisor removes that directory when the hook ends, on SIGTERM after killing the hook's process group, and in a `finally`; a supervisor killed with SIGKILL leaves it for `reconcile`), runs through `sh -c` in its own process group, with no `{...}` substitution and the environment of gatectl. Unlike a script check (a scrubbed allowlist), a hook receives the whole environment of the caller, secrets included, plus the reserved `GATECTL_HOOK`, `GATECTL_ID` and `GATECTL_OBJECT_TYPE`, which gatectl always sets whatever the caller's environment says. Its stdout and stderr are connected to `/dev/null` and every descriptor above 2 of gatectl is closed in the child: a hook never holds a descriptor of the caller. Every child gatectl starts (the hook supervisor, a hook, the lifeline watchdog, a script check, a `session_cmd` call) gets explicit stdin, stdout and stderr (`/dev/null` or a private pipe gatectl reads) and `close_fds`, so no child ever inherits a descriptor of the caller; a gatectl killed with SIGKILL leaves no process holding the caller's pipes. The supervisor handles SIGTERM by killing the hook's process group and removing its directory. Hook output is discarded; the exit status, the timeout and a skipped hook are written to `log.jsonl` (a non-zero exit or a timeout as `hook_failed`, a skipped hook as `hook_skipped`). A hook's stdin is that file itself, opened read-only without following a link (so it is seekable, and a hook that never reads it blocks nothing), and its working directory is `/`. A hook's failure is never fatal. Payloads carry no input text and no `labels` key (gatectl stores no labelled objects). Common keys: `tool` (`gatectl`), `hook`, `object_type`, `object_id`, `repo` (nullable).

**Timing.** A result is printed before any hook runs. For `check`, every hook (the only one it fires is `post-decision`) runs detached whatever its `async` value says: a supervisor process in its own session applies the hook's `timeout` and kills the hook's process group, and `check` exits without waiting for it. For `outcome` and `set`, the result is printed first; an `async: false` hook is then awaited within its timeout and an `async: true` hook is detached as above. Hooks of one event run one after the other in config order; for `set --all`, one `post-state-change` fires per scope that changed. Hooks are fired after the commit, never inside a transaction.

**Supervisor.** `check` starts the supervisor (`python -I -m gatectl.supervisor`) after it printed the result and pointed descriptors 0, 1 and 2 at `/dev/null`, so the supervisor can inherit none of the caller's; it is started with explicit `/dev/null` for stdout and stderr, a private pipe for stdin, `close_fds` and a session of its own, and gatectl hands it one job on that pipe (the hooks of the event, the payload, the log labels) within 2 s, else kills it and logs `hook_skipped` (`handoff_failed`) and exits without waiting for it. The payload travels only in that job and in `payload.json`, never in argv or the environment. The supervisor creates each hook's directory itself, so its `owner` names the supervisor, runs each hook through the same group-kill sequence as a script check (SIGTERM to the hook's group at the timeout, SIGKILL after 2 s, a sweep of the group when the hook exits, and the lifeline watchdog that kills the group if the supervisor itself is killed), and catches SIGHUP and SIGINT without acting on them (a handler, not an ignore: a hook starts with default dispositions for both and can trap them). It is started as `python -I -m gatectl.supervisor`, which ignores `PYTHON*` variables, the user site and the working directory, so gatectl must be an installed package of that interpreter; running from a source tree through `PYTHONPATH` is unsupported for hooks, and a supervisor that cannot start is silent (no hook runs and nothing is logged). A failure is a `hook_failed` event whose `data` is `{"index": <position in the event>, "reason": "exit" | "signal" | "timeout" | "terminated" | "not_started" | "lifeline_lost", "exit_code" | "signal": <n>, "leader_unkilled": true}` (`leader_unkilled` only when the hook's leader survived SIGKILL and was not reaped); a hook directory that cannot be removed is a `warning` event whose `data` is `{"index": <n>, "reason": "workdir_left"}`; a hook that never started is a `hook_skipped` event with `data.reason` one of `busy`, `no_slot`, `directory`, `too_many_hooks`, `invalid_command`, `invalid_environment`, `payload_invalid`, `payload_too_large`, `terminated`, `handoff_failed` or `not_started`. `data.index` is present when the skip concerns one hook, decided by the runner (`directory`, `too_many_hooks`, `invalid_command`, `invalid_environment`, `terminated`, and `payload_invalid` or `payload_too_large` for a payload found bad there), and absent when the whole event was not run (`busy`, `no_slot`, `handoff_failed`, `not_started`, and `payload_invalid` or `payload_too_large` found by the launcher, which includes a job over the frame cap of 576 KiB). The command text is never logged. Bounds: an event runs at most 64 hooks (the rest are skipped), a payload is at most 256 KiB, and at most 16 supervisors run hooks at once, machine-wide (each holds one `flock` on `hook-slot-<n>.lock` in the state directory, which the kernel releases when it ends however it ends); one that finds all 16 held logs `hook_skipped` (`busy`) and ends. A check that was killed after printing but before starting the supervisor fires no hook.

| Hook | Fires | `object_type` / `object_id` | Other keys |
|---|---|---|---|
| `post-decision` | after a decision is recorded and committed | `decision` / the decision id | `policy`, `scope`, `state`, `shadow`, `enforced`, `decision`, `reason`, `fingerprint`, `actor`, `checks` (name, type, verdict, reason, duration) |
| `post-outcome` | after an outcome is recorded | `outcome` / the decision id | `policy`, `scope`, `outcome`, `signal`, `actor`, `effective_outcome`, `previous_effective_outcome`, `miss` |
| `post-state-change` | after `set` changed a state or wrote a row (one hook per scope written; not for a re-enforcement of an unchanged state), or the automatic drop wrote one | `policy` / the policy name | `scope`, `state`, `previous_state`, `cause` (`set` or `miss`), `actor`, `decision_id` (for `miss`) |

Hook environment: `GATECTL_HOOK`, `GATECTL_ID` (the object id) and `GATECTL_OBJECT_TYPE`. These names are reserved and never read as config. Wire `post-state-change` to a notification: an automatic drop to shadow is the event a human should hear about.

### Using gatectl as a hook

A caller wires a gate as a `pre-` hook, for example `cmd: "gatectl check start-work --timeout 540"` with `timeout: 600`. The caller's `pre-` hook rules apply to the exit code (0 continues, 13 escalates, anything else vetoes) and the printed `decision_id` is recorded in the caller's audit entry. A hook that launches claude-session sessions must exclude the `gate-check` kind. The README has the wiring checklist.

`session_cmd[0]` is either an absolute path or a bare file name. A bare name is searched only in `~/.local/bin`, `/usr/local/bin`, `/opt/homebrew/bin`, `/usr/bin` and `/bin`, in that order, never through the caller's `PATH`; the first regular executable file is used by its absolute path for every call. A name containing `/` that is not absolute is a config error. `validate` prints the resolved path and reports `session_cmd_unresolved` when none is found; the probe hash uses the resolved path.

**Ranges.** A value outside its range is an `invalid_value` config error: `defaults.timeout`, a policy `timeout` and `--timeout`: greater than 0 and at most 86400 s; `defaults.script_timeout`, a check `timeout`, `agent.timeout`, a hook `timeout`: greater than 0; `agent.min_start_budget`: at least 1 s; `defaults.record_reserve`: 100 ms to 60 s; `defaults.input_max_bytes`: 1 to 16777216; `agent.input_max_bytes`: 1024 to 1048576; `agent.max_parallel`: an integer from 1 to 32; `agent.threshold` and a check `threshold`: 0 to 1; `recommend.confidence`: above 0 and below 1; `recommend.max_miss_rate`: above 0 and at most 1; `cache_ttl` (any level): `0` (off) or a duration; `retention.older_than`: null or a duration greater than 0.

The file as a whole (YAML syntax, unknown top-level keys, `me`, `session_cmd`, `defaults`, `agent`, `retention`, `hooks`, the `repos` structure) is validated at load. A failure in the shared part exits 2, naming the key, for `check`, `reconcile`, `prune`, `cron` and `set ... enforced`. The other commands (`set ... off|shadow`, including `--all`, `outcome`, `show`, `decisions`, `stats`, `policies`, `export`) need only a file that parses as YAML: they use the built-in default for an invalid shared key, add the warning `config_problem` to their result (or a line to stderr) and carry on, so the kill switch and the fail-safe commands work whenever the file can be read; `validate` lists the problem. `set <policy> off|shadow` and `outcome` accept any policy name that is in the file or in `state.db`, even one whose own definition is invalid. Each policy and each `repos.<id>.policies.<name>` is validated separately: `check <policy>` fails (exit 2) only when that policy or its override for the scope is invalid; other invalid policies add the warning `config_problem` to its result and are listed by `validate`. A policy that is invalid also fails `set <policy> enforced` (the fingerprint needs its definition). An unreadable config file is an unknown state (exit 1). Resolution of binaries, files, skills and plugins is never done at load; it happens per check (Script checks, Agent checks) and failures escalate with `tool_missing`. `validate` does all of it eagerly.

**Reading the files.** Each config file is opened without blocking and must be a regular file (a symlink to one is followed; a directory, FIFO or device is unreadable); a file is at most 1 MiB, all files together at most 4 MiB, and `config.d` holds at most 256 files. Drop-ins are the non-hidden files named `*.yaml` (not `.yml`, not dotfiles), sorted by code point. A missing default config file is an empty config; a missing `--config` file is unreadable (exit 1). The text must be UTF-8 and one YAML document of plain data: anchors, aliases, merge keys (`<<`), duplicate keys, non-string keys, tags beyond the core ones, timestamps, binary and set values, non-finite numbers, lone surrogates and nesting deeper than 64 levels are config errors (exit 2 in every command, naming the file, and the line when known, never the text). An environment variable that names a config key outside the listed ones (for example `GATECTL_AGENT__SANDBOX`) is an `invalid_value` problem of the shared part and is never applied; so is one whose first `__`-separated segment after `GATECTL_` is a config section (matched case-insensitively, ASCII only) but whose name is not exactly a listed key in upper case, whatever its characters (`GATECTL_HOOKS__POST-DECISION`, `GATECTL_AGENT__timeout`; the problem never repeats the name); a listed key with an invalid value is a problem too and the file's value stays; a `GATECTL_` variable whose first `__`-separated segment is not a config section is ignored (`GATECTL_HOOK`, `GATECTL_AGENT_TIMEOUT` with one underscore, `GATECTL_HOOKS-X__Y`). A glob pattern is at most 128 characters as written (a run of three or more `*` is one `**`). Error paths name keys with unknown key names sanitized and cut to 64 characters.

Precedence for config values is flags > per-repo override > environment variables (only the keys listed in Environment variables) > config (the global file, then drop-ins in lexical order, a later drop-in winning) > built-in defaults. A per-repo override sets policy keys (`timeout`, `cache_ttl`, `checks`, ...), so it beats every `defaults.*` and `agent.*` value, an environment value included; it is not a layer of the `defaults` and `agent` keys (Per-repo overrides). A policy's `state` in the config is only its initial state. The bundled permission profile, sandbox level, setting sources and env allowlist can each be replaced by the keys above, so a more permissive or stricter setup never depends on another tool's config.

Timing and reuse keys, from the strongest to the weakest source:

| Value | Order |
|---|---|
| total deadline | `--timeout`, then the repo override's `timeout`, then the policy's `timeout`, then `defaults.timeout` |
| a check's budget | the check's `timeout`, then `agent.timeout` (agent) or `defaults.script_timeout` (script), capped by the remaining budget |
| reuse window | the check's `cache_ttl`, the policy's `cache_ttl`, `agent.cache_ttl` |

## Audit and log

`~/.local/state/gatectl/audit.jsonl` is appended for every decision, outcome, state change and prune; `log.jsonl` holds structured events. Both are public, append-only contracts (`schemas/audit.json`, `schemas/log.json`; the schemas give the shape and this section the rules).

| Audit `action` | Fires | `target` | `result` |
|---|---|---|---|
| `decision` | a decision was recorded | `<policy>@<scope>` | decision, reason, state, shadow, enforced |
| `outcome` | an outcome was recorded | the decision id | outcome, signal, effective outcome, miss kind |
| `state_change` | `set`, or the automatic drop | `<policy>@<scope>` | previous and new state, cause, reason (for cause `miss`, the triggering outcome's sanitized reason), `triggered_by` (the decision id for cause `miss`, else null) |
| `prune` | a non-dry-run call deleted rows | `state.db` | counts, the age |

A decision's record carries `actor`, `decision_id` (the decision's own id), the `input_sha256`, the fingerprint and the policy, never the input. Every record carries `stdin_tty` at its top level, and its `inputs` carries `decision_ids` (the caller's `--decision-id` values, an empty array when none) and `actor_source` (`flag` or `default`), so `human:` with `stdin_tty: false` is visible; the per-action `inputs` and `result` shapes are in `schemas/audit.json`. Schema creation and migration commit in their own transaction before any decision is inserted or any audit line is appended, so a `state.db` without a schema (or of zero length) next to a non-empty audit log can only come from outside gatectl (`state_db_missing`). The record is appended inside the transaction that inserts the decision, before the commit, so a returned decision always has an audit line (a crash can leave a line for a decision that did not commit, never the reverse). A `check` while the policy is `off` writes a log event only. A refused `set` (exit 20) is not audited (a `warning` log event). A decision's time is the instant of its step 8 insert (inside the transaction). Every line of both files is written with a single `write` on a descriptor opened with `O_APPEND`, and a line over 64 KiB is capped before writing (its free-text fields are shortened until it fits), so concurrent writers never interleave. Lines are ASCII-only JSON: non-ASCII characters are written as `\uXXXX` escapes. A short or failed `audit.jsonl` write (a full disk) is never truncated back, because another writer's line may follow it: the transaction fails, and the partial line stays; `log.jsonl` is never truncated either. The next writer of either file reads the file's last byte (through the descriptor it is about to write, under an exclusive `flock`); when the file is non-empty and does not end in a newline, it puts one newline in front of its record in the same single write, so the record is a line of its own and the partial line is skipped by a consumer. That newline ends the previous line and does not count against the new line's 64 KiB cap (the line itself never exceeds 64 KiB; the physical write can be 64 KiB plus one byte). A file that ends in a newline, or is empty, gets no prefix, so normal operation writes no blank line. A consumer skips a line that does not parse and reports it. Retention is forever.

The log event names are closed: `check_off`, `shadow_failure`, `hook_skipped`, `hook_failed`, `reconcile`, `drop_skipped`, `terminated`, `cron` and `warning`. The warning codes in a check result are the closed list in Check result.

## Files

| Path | Contents |
|---|---|
| `~/.config/gatectl/config.yaml`, `config.d/*.yaml` | config |
| `~/.local/state/gatectl/state.db` | SQLite, WAL, private: state rows, decisions, outcomes, cache, slots, `meta` (schema version, probe markers) |
| `~/.local/state/gatectl/audit.jsonl`, `log.jsonl` | public contracts |
| `~/.local/state/gatectl/tmp/<decision_id>/` | one directory per `check` process, mode 0700, created the first time a check needs one and removed when the check ends: `owner` (the creating process's PID, start time and boot id as one JSON object `{"pid", "start", "boot_id"}`, written first), `s-<n>/` (the private working directory of the n-th script check, removed when that script ends), and for an agent run `input.json` and `prompt.md` |
| `~/.local/state/gatectl/tmp/hook-<random>/` | one directory per detached hook run: `owner` (the supervisor) and `payload.json` (mode 0600) |
| `~/.local/state/gatectl/hook-slot-<n>.lock` | 16 empty advisory-lock files (mode 0600), `<n>` from 0 to 15: the concurrency bound of the hook supervisors (Hooks) |

The state directory is `$XDG_STATE_HOME/gatectl`, else `~/.local/state/gatectl`; no other override exists (tests set `XDG_STATE_HOME`). The directory has mode 0700; `state.db`, its `-wal` and `-shm` files, `audit.jsonl` and `log.jsonl` have mode 0600, set explicitly, not through the umask; an existing directory or file is tightened to 0700 or 0600, and one not owned by the user (or, for the two JSON-lines files, not a regular file) is refused. A relative or empty `XDG_STATE_HOME` is ignored. A state directory that is a symlink or not a directory is refused with an explicit message (never followed), as is one owned by another user; a missing one is created 0700 whatever the umask. Every `tmp/` directory and file is created exclusively and without following links.

**Removal of `tmp/` trees** (the end of a check, a script check's `s-<n>/`, and `reconcile`) first opens the directory's parent without following a link (a parent that is a link, not owned by the user or not openable is refused, never treated as "already gone"), then walks with directory file descriptors, never follows a link (a link is unlinked, not entered), never crosses a mount point, makes each directory writable before deleting its contents, deletes the `owner` file last, and on anything unexpected (a directory that is not owned by the user, a file type it did not create, a changed device) refuses to go further, reports it (a `warning` log event) and leaves the directory to the next `reconcile`. A removal problem never changes a script check's verdict; it only sets the check's `workdir_left`.

Policy files, `instruction_file`s and script paths must be outside every path an isolated Claude session can write, like every other tool's config.

## Labels

gatectl stores no labelled objects and has no label commands. Its claude-session sessions carry `owner=gatectl`, `policy=<name>`, `decision=<decision_id>` and `state=<tag>`, where `<tag>` is the first 12 hex characters of the SHA-256 of the realpath of the state directory (symlinks resolved, so every spelling of the path, a cron run's included, gives one tag).

## TUI

None in v1. A `browse` view of decisions and track records is a 1.x candidate.

## Upgrades

`state.db` migrations are additive only; a database from a newer gatectl is refused (exit 1, `schema_newer`) without touching it. Policy fingerprints change only when the rules in Fingerprint change, which starts fresh records.

## Residual risks

- The partial-line newline is a check then a write. gatectl's own writers hold an exclusive `flock` across both, so they cannot race each other. The wait for the lock is bounded (about 1 s, under the 2 s a decision's database write lock is held); on timeout, or when the filesystem does not support `flock` (ENOLCK, EOPNOTSUPP, ENOSYS, EINVAL), the line is written without the lock, and any other `flock` error fails the write. A writer without the lock (the timeout, an unsupported filesystem, or another program that ignores it) can fuse its record onto a partial line it did not see, or add a blank line when two writers both terminate the same partial line. A consumer skips a line that does not parse, and a blank line is skipped too.
- A same-user process, including a prompt-injected trusted agent, can pass any `--actor`, so the human-only rules (`set ... enforced`, counting an `agree`) are advisory against it. They stop automation that does not lie.
- Lowering an enforced scope with `set shadow|off` (any actor) or with an `outcome ... disagree` on an enforced `allow` (any actor; ids are listed by `decisions`) removes a veto gate's veto. A prompt-injected agent in the same account can do either. Wire `post-state-change` to a notification.
- A trusted same-user agent can rewrite the config, instruction files, scripts, the plugin and the bundled permission profile; policy, instruction and script paths must be outside every path an isolated session can write (Files). gatectl warns on a changed definition under an enforced scope (`definition_changed`) and does not prevent it.
- A check killed with SIGKILL after it closed its output but before it finished handing its hook job to the supervisor (the window covers the job handoff itself, not only the start) drops that event's hooks: a half-delivered job is discarded by the supervisor without a log line.
- A script check that calls `setsid` leaves its process group and is not killed on a timeout.
- A script check that creates a FIFO, socket or device node in its working directory leaves that directory behind (removal refuses file types gatectl does not create, Files); it is reported (`workdir_left`) and removal is left to the operator, because `reconcile` applies the same rules.
- A script check leader that survives SIGKILL (uninterruptible sleep) is not reaped: gatectl waits at most the timeout plus the 2 s kill grace plus 5 s, then gives up and reports the check by its cause (timeout, cancel or lost lifeline; `leader_unkilled` is set on the outcome). Its watchdog is kept with its lifeline open, so the group is left until gatectl exits, when the watchdog kills it.
- gatectl dying between starting a check and writing the `G <pgid>` line to the watchdog (microseconds) leaves a check nobody stops.
- An exit code of 256 wraps to 0 and reads as `allow`.
- Fencing and the nonce do not stop a model from being steered; an agent check can only tighten a decision, and a deterministic check must back every automatic action. Agent confidence is not calibrated. A `model` of `null` follows Claude Code's default, which a Claude Code update can change.
- Claude Code's transcripts of gate-check sessions stay under its projects directory after `forget`. After `forget`, claude-session also keeps the session's staged input, prompt and result for `retention_days` (default 30), deleted only by its `reconcile`. For sensitive inputs, run claude-session's `reconcile` under cron and set a low `retention_days`.
- The sandbox's containment of a gate-check session was shown by configuration only; a live injection attempt that tries to read outside the session has not been observed to succeed or to be refused.
- `claude-session --dry-run` can report the sandbox as available for a setup that fails at run time; `validate --probe` is the check.
- If gatectl is killed with SIGKILL, running script checks are killed by the lifeline watchdog and a live agent run is found by label and stopped by the next `reconcile` (run it under cron).
- A policy edited between a decision and its outcome keeps the old fingerprint: the outcome counts toward the old record.
- Every distinct input can cost one agent run (bounded by `max_parallel` and the cache); a flood can make other checks `busy`.
- `GATECTL_*` timeout and limit variables inherited from a caller change deadlines; safety keys are not environment-settable.
- A caller whose `HOME` or `XDG_STATE_HOME` differs from the operator's reads another state directory (an empty one starts every policy at its initial state).
- The repo comes from the caller's payload: it selects a configuration and is not a security boundary, and its spelling must match exactly.
- The rule language has no cross-field comparison, list quantifiers or lengths; a policy that needs them uses a script check.
- `shadow` and `off` disable veto gates; a decision id references a decision and does not prove which revision it judged (compare the declared fields from `show`).
- A config error in the shared part, or an invalid definition of the wired policy, makes `check` exit 2, which a hook caller counts as a veto even in shadow (the state is unknown); run `validate` before saving, and use `set <policy> off --all` to stop a policy's automatic actions meanwhile.
- Re-adding a removed policy name resumes its stored rows, as editing a policy in place does (with a `definition_changed` warning when the definition differs); lower the rows with `set <policy> shadow --all` before removing a policy.
- State grows without bound: every distinct input is a decision row, current-fingerprint decisions are never pruned, and `audit.jsonl` and `log.jsonl` are never pruned. A flood of distinct inputs can fill the disk, after which every `enforced` check exits 1. Watch the state directory's size; archive the two JSON-lines files with `export --since` and rotate them from outside (gatectl opens each file for every append, so a rename-based rotation is safe).
- `applies_when` is a scoping filter, not a detector: a condition over text an attacker writes can be dodged, and a `not_applicable` answer never authorizes an automatic action (it carries `enforced: false`).
- The probe does not cover per-check safety overrides (`sandbox`, `skill`, `permission_profile`, `setting_sources`, `env_allowlist`, `model`); `validate` still checks them.
- A slot holder that never ends (stopped or in uninterruptible sleep) keeps its slot; `reconcile` names its PID in `overdue_holders`, and `kill -9` of that exact PID frees it.
- Refused `set ... enforced` calls are not rate-limited: each writes one `warning` log event (no audit record), so a loop of refused calls grows `log.jsonl` without bound.
- The state directory must not be shared across PID namespaces (a container and its host): holder liveness reads `/proc`.

## Platform notes

Linux, WSL and macOS are supported. Detached hooks start `python -I -m gatectl.supervisor`; `-I` ignores `PYTHON*` variables, the user site and the working directory, so gatectl must be an installed package of the interpreter that runs it (a source tree on `PYTHONPATH` does not work for hooks), and a supervisor that cannot start is silent. Agent checks need claude-session and its required sandbox: `bubblewrap` and `socat` on Linux and WSL2, Seatbelt on macOS; WSL1 has no sandbox. The lifeline watchdog uses a pipe, not `PR_SET_PDEATHSIG`, so it works on every platform. Slot liveness uses the holder's PID and process start time, read by a per-platform method (with the boot id). The state directory must not be shared between PID namespaces (a container and its host): holder liveness reads `/proc`, so another namespace's holders would look dead. A container that runs gatectl needs an init process that reaps children (for example `docker run --init`). A holder that never ends (stopped or in uninterruptible sleep) keeps its slot; `reconcile`'s `overdue_holders` names its PID, and `kill -9` of that exact PID frees it. On macOS the group-sweep handshake of Script checks cannot use `waitid` if the interpreter lacks it: completion is detected with a `kqueue` `EVFILT_PROC` / `NOTE_EXIT` watch, which does not reap, and where neither exists the leader is not reaped before the group sweep. Install claude-session with copied, not hard-linked, files (`UV_LINK_MODE=copy`) and an interpreter that does not go through a link outside the sandbox's readable directories. gatectl's bundled plugin directory ships the placeholder files `.claude/`, `.mcp.json`, `CLAUDE.md` and `CLAUDE.local.md`, because a sandboxed session refuses a read-only plugin directory without them. File watching is not used.
